## Differences from the specification, and why
- **The methods are `structured` and `stream`** (F5's `AiGateway`), not `complete` and `stream`.
- **Effort, token limit and timeout overrides are read in `createGateway`** from `process.env` (`AI_EFFORT_<ROUTE>`, `AI_MAX_TOKENS_<ROUTE>`, `AI_TIMEOUT_MS_<ROUTE>`), because `GatewayConfig` and the API's `loadConfig` carry only the models and must not change. An invalid value throws when the gateway is built, so the API fails at start. `opts.routes` overrides this.
- **The gateway does not load prompts itself.** F5's request types carry `system: PromptBlock[]`, so the route owner builds the blocks with `systemFor(route, tail)` from the registry. The registry reads F5's map `prompts/index.ts`, which imports every folder's `index.ts`.
- **One cache marker**, on the last block marked `cache: true` (`cache_control: { type: 'ephemeral' }`, 5 minutes). The conversation history is not marked. A second marker on the last message would make later tutor turns cheaper. It can be added in `systemBlocks`/`buildRequest` once real usage shows the prefix is above the minimum cacheable size.
- **No `thinking` parameter is sent.** Claude Opus 5.5 runs adaptive thinking by default and rejects `disabled`, so effort is the only control; the token limits leave room for thinking. A route moved by `AI_MODEL_<ROUTE>` to an older model (Opus 4.8 or earlier) would run without thinking.
- **No server side refusal fallback** (`fallbacks`, beta `server-side-fallback-2026-07-01`). The specification asks for a typed refusal, so `stop_reason: refusal` becomes `AiGatewayError('refused', …, { category })`. The fallback can be added later as a one line request change if refusals turn out to be false positives.
- **The stubbed SDK client is the real `Anthropic` client with a stub `fetch`**, not a hand written fake. The SDK's own request building, server sent event parsing, retries and error classes run in every test.
- **The budget check is `spent >= budget` before each call.** A call that starts under the budget finishes even if it goes over. The next call is refused.
- `packages/ai/package.json` got the script `smoke` (allowed: owner scripts). No dependency changed.

## Notes for packages that depend on this one

### Route owners (B4, B9): write a prompt version
```ts
// packages/ai/prompts/tutor.reply/v2.ts
import type { PromptVersion } from '../../src/prompt';
export const v2: PromptVersion = {
  version: 2,
  system: [
    { text: 'You are a Slovak tutor … (role and rules)' },
    { text: 'Error checklist: …', cache: true },   // end of the stable, cached part
  ],
};
// packages/ai/prompts/tutor.reply/index.ts: versions: { 1: v1, 2: v2 }, current: 2
```
Stable blocks hold no dates, names, ids or other values that change per request: `registry.test.ts` fails otherwise. Keep old versions for the evals. Per request text (scenario, directive, learner level) goes in the tail and is never cached.

### Calling the gateway (`deps.ai`), between transactions, never inside one
```ts
import { systemFor, isAiGatewayError } from '@app/ai';

// JSON checked against a zod schema
const { data, usage } = await deps.ai.structured({
  route: 'tutor.analyze',
  userId,
  system: systemFor('tutor.analyze', [`Scenario: ${scenario.brief}`]),
  messages: history,            // [{ role: 'user' | 'assistant', content }]
  schema: AnalysisSchema,
  signal,                       // optional: the client went away
});

// Streamed text
const { text } = await deps.ai.stream({
  route: 'tutor.reply',
  userId,
  system: systemFor('tutor.reply', [directive]),
  messages: history,
  onText: (delta) => send({ event: 'delta', data: { text: delta } }),
  signal,
});
```
- Errors are `AiGatewayError` with `code`:
  - `budget_exceeded` (`details.resetsAt`, no model call)
  - `refused` (`details.category`)
  - `truncated`
  - `upstream_failed` (`details.reason`: `invalid_output`, `timeout`, `connection`, `rate_limited`, `overloaded`, `auth`, `provider_error`, `bad_request`, `unexpected_stop`; plus `status` and `requestId` when known)

  The platform maps them (budget → 429, others → 502). An aborted call rejects with a `DOMException` named `AbortError`.
- **A stream can fail after pieces were sent** (a refusal or a cut off at the end). Then the caller must send the `error` event and drop the partial reply, and store nothing of it.
- Schemas: the zod schema is turned into a JSON schema for structured output. Keep to what structured output supports (objects, arrays, strings, numbers, enums, optional fields). Numeric bounds and refinements are checked by zod after the answer, and a failure becomes `upstream_failed` / `invalid_output`.
- Every call writes exactly one usage row (status `ok`, `refused`, `truncated` or `error`), including failed and aborted ones.
