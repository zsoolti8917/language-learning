# C1 Morphology import
Status: done

## What was built
The content pipeline's command line tool, its stage runner and validation framework, and the stages `fetch`, `morph`, `validate` and `load` in `tools/pipeline/src/`. Also `content/SOURCES.md` and the lemma registry `content/registry/lemma-ids.tsv` (100,681 ids).

| Piece | Where | Does |
|---|---|---|
| CLI | `src/cli.ts` | `pnpm run pipeline <stage> [--force] [options]`, `pnpm run pipeline list` |
| Stage runner | `lib/runner.ts` | `Stage` interface, `runStage`: fingerprints inputs (sha256, cached by size and mtime), the stage's code folder plus `lib/`, and `params`; skips a stage whose fingerprint did not change and whose outputs are intact. A file that is input and output (the registry) is fingerprinted after the run. State in `content/build/.state/<stage>.json` |
| Validation | `lib/validate.ts` | `Check`, `CheckContext`, `validateSet(dir, checks, { registry, complete })`. Core checks: `schema` (F3's `validateContent`), `unique`, `links` (lemma, pattern, trigger, lesson, exercise, sentence token and link, library analysis), `tags` (each tag parses with `@app/ling` and fits its lemma's part of speech), `registry` (ids and keys agree; in a complete set no registered id is missing) |
| Set assembly | `lib/set.ts` | `SetPart` (`rows` or `merge` by key), `assembleSet`: writes `content/build/set/` and its manifest; an unchanged rebuild keeps the old manifest, a changed one gets the next `YYYY-MM-DD.N` |
| Registry | `lib/registry.ts` | `LemmaRegistry` (assign, `assignAll` in code point order, append-only `saveRegistry`), `lemmaKey`, `parseLemmaKey` |
| Sources | `lib/sources.ts` | Catalog of all six sources with URLs, licences and sha256; `source.json` record per source; the generated table in `content/SOURCES.md` |
| Streams | `lib/lines.ts`, `lib/files.ts` | `readLines` for plain, `.gz`, `.xz`, `.bz2` (system `xz`/`bzip2` through `child_process`), `readJsonl`, `JsonlWriter`, `writeFileAtomic`, `stableJson` |
| `fetch` | `stages/fetch` | Copies a source from a local folder (`--from`, `PIPELINE_RAW_FROM`, or `/mnt/project-files/raw-data`) or downloads it, checks the sha256 against the catalog (refuses a changed file without `--allow-changed`), writes `content/raw/<id>/source.json` and the row in `content/SOURCES.md` |
| `morph` | `stages/morph` | Streams the SNK file → `content/build/morph/{lemmas,forms}.jsonl`, the registry, `report.md` / `report.json`. `snk.ts` maps the tagset, `patterns.ts` assigns patterns, `overrides.ts` holds the mini dataset's lemma decisions, `measure.ts` measures `ling.form` in PGlite, `compare.ts` compares with the mini dataset. Adds the checks `morph.prep-cases` and `morph.noun-patterns` |
| `validate` | `stages/validate` | Assembles the set from every stage's parts, runs core and stage checks, writes `content/build/validate/report.md`; fails on any issue. `--dir <folder>` checks an existing set (e.g. the mini dataset), `--complete`, `--no-registry` |
| `load` | `stages/load` | `loadContent` on the set; `--rank-limit N` keeps lemmas ranked 1..N plus every lemma another file points at (`limitSetByRank`); `--pglite <dir>`, or `DB_MODE=pglite` / `PGLITE_DATA_DIR`, or `DATABASE_URL` (as `pnpm db:load`). Migrates first in PGlite mode |

Mapping (`snk.ts`): S → noun (gender m/i/f/n → `m_anim`/`m_inan`/`f`/`n`, tag number+case), A and G (participles) → adj (tag number+case+gender), P → pron (gender h → `x`+case; a pronoun with one gender and one number, like *kto*, *čo*, also gets `x`+case), N → num, PD and ND → adv, V → verb (`v:` + the SNK tag without `V`, aspect d/e/j → pf/ipf/both, taken from the infinitive), D → adv, E → prep (governed case kept), O → conj, T → part, J → intj, R, Y, W, Q, % → other. Dropped: entries marked as errors (`*` before lemma or form, or `:q`), comparatives and superlatives (`y`, `z`). Flags: `proper` (capital initial on a noun or adjective, or `:r`), `pluralOnly`, `indeclinable` (one form, several tags), `irregular`, `retired` (registered key the source lost), `cases` on prepositions. Lemma key `lemma|pos|gender|1`.

Patterns (`patterns.ts`): chosen from gender, animacy, the SNK paradigm letter (F → kuli, gazdiná; A → adjectival noun; U → indeclinable) and the endings of the nominative and genitive singular (the nominative plural separates dub and stroj; plural only nouns go by the nominative plural). The pattern is then tested on s3, s7, p1, p3, p7 from the stem of the genitive (accents folded); a noun that fails keeps its pattern and gets `irregular`, as the mini dataset does for *deň*. Adjectives: AF → otcov, -ý/-y → pekny, -í/-i → cudzi.

## How to run and test it
- `pnpm test --filter pipeline` (76 tests, about 25 s, PGlite included), or `pnpm check` (passes).
- Full run (recorded): `pnpm run pipeline fetch --source snk-morphology` → `pnpm run pipeline morph` → `pnpm run pipeline validate` → `pnpm run pipeline load --pglite .local/pgdata`.

Tests prove each item of "Done when":
- Streaming and validate: `morph.test.ts` runs the stage on a 979 line SNK excerpt (`stages/morph/fixtures/snk-sample.txt`, plus a tiny `.xz`), `validate.test.ts` assembles that output into a set and validates it, and validates the mini dataset with every check. Broken sets (dangling lemma, duplicate form, wrong tag, unknown trigger and pattern, registry mismatch, missing id) fail with the expected messages.
- Golden tables: `morph.test.ts` holds hand checked tables for *mesto, žena, chlap, stroj, ulica, dievča, ľudia, múzeum, pekný, ja*.
- Patterns: `patterns.test.ts` reproduces the pattern and irregular flag of every mini noun; the full run reaches 98.25 % (below).
- Rerun: `morph.test.ts` runs the stage, checks the runner skips it, forces it and compares every output and the registry byte for byte. On the full data, a forced second run gave identical sha256 for both jsonl files, both reports and the registry.
- Mini comparison: the morph report compares with `packages/testkit/mini` (see below).
- Also tested: registry append-only rules, the runner's skip logic, SOURCES.md round trip, fetch (local copy, download, checksum refusal, no-op rerun), set assembly with a `merge` part and version bump, `load` with a rank limit into PGlite, the size measurement.

Quality highlights: no unknown tags in the whole file; the 50 random nouns all look right (e.g. *prax* dlaň, *pocit* dub, *drvič* stroj, *nacista* hrdina, *krovie* vysvedčenie); irregular nouns are mostly truly irregular (*deň, dieťa, idea, knieža, chuť, pánboh, peso*). Mini dataset: every one of the 72 lemma ids has the same key in the registry, and every one of the 601 forms and their tags equals the real data; the built lemma rows also equal the mini rows in gender, pattern, aspect and flags (apart from the new `flags.cases` of the prepositions). **No change to `packages/testkit/mini/` was needed.**

## Differences from the specification, and why
- **`pnpm pipeline` is a built-in command of pnpm 12** ("Runs a named pipeline of workspace tasks") and shadows the root script. The command is `pnpm run pipeline <stage>`. The root script is unchanged (a root file); a follow-up for F1 could rename it or update the docs.
- **Prepositions' cases are in `flags.cases` in `lemmas.jsonl`, but not in the database**: `LemmaFlagsSchema` (contracts) has no such key, and zod strips it when the loader parses the row. C4 reads the file, which is enough for its check. A shared surface PR can add `cases: Case[]` to `LemmaFlagsSchema` to carry it into `ling.lemma.flags`.
- **Misspellings**: this SNK release marks errors with a `*` before the lemma or the form (*Marek → \*Mareka*), not with `:q`, and has no `:r` either. Both markers are handled; proper names are flagged by a capital initial.
- **páví** is never assigned: in SNK its forms equal cudzí's, so no rule can separate them. **otcov** is assigned (63 lemmas). Neither has a row in a patterns file yet (C4 owns them).
- A noun whose pattern fails the test keeps the pattern and gets `irregular`, like the mini dataset's *deň* and *človek*; "irregular gets a flag instead" is read as "in addition".
- Hand decisions (`overrides.ts`) keep the F9 lemmas: *tá* and *to* (pronoun) are filed under *ten*; the plural of *človek* is the plural only lemma *ľudia* (irregular, no pattern); *človek* is irregular.
- Comparatives and superlatives are left out (as in F9): the tag cannot say so, and they would pass as positive forms.
- `morph.noun-patterns` is an issue only on sets of 1,000 nouns or more (a warning on samples); `morph.prep-cases` is an issue only in a complete build (the mini prepositions have no `flags.cases`, a warning there).
- The registry was started from the mini dataset's 72 keys; new keys were numbered from 73 in code point order of the key.

## Known gaps and follow ups
- No live download was tried (the shared folder was used); `fetch` uses Node's `fetch`, which honours `HTTPS_PROXY` only with `NODE_USE_ENV_PROXY=1` (Node 24).
- `.xz` and `.bz2` need the system `xz` / `bzip2` (present in CI and here). No new dependency was added.
- The validate stage's fingerprint covers its own code and `lib/`, not other stages' check code: after changing a check, run `validate --force`.
- No patterns file in the set yet, so `links` warns that lemma patterns are unchecked until C4 adds `patterns.jsonl` (it must then hold all 17 ids used: the 14 noun patterns, `pekny`, `cudzi`, `otcov`).
- The 277 adjectival nouns (*vedúci, spolutrpiaci*) and 348 indeclinable nouns have no pattern; B5 should treat them as outside the pattern drills.

## Notes for packages that depend on this one
- **Add a stage** (C2–C5): create `tools/pipeline/src/stages/<name>/index.ts` exporting a `Stage`:
  ```ts
  export const freqStage: Stage = {
    name: 'freq',
    description: 'Ranks and top forms',
    sources: ['araneum-arf', 'frequencywords/sk_full.txt'],    // id, or id/file
    codeDir: codeDirOf(import.meta.url),
    options: { limit: { type: 'string' } },                    // node:util parseArgs format
    inputs: (ctx) => [join(ctx.paths.raw, 'araneum-arf'), join(ctx.paths.build, 'morph', 'lemmas.jsonl')],
    outputs: (ctx) => [join(ctx.paths.build, 'freq', 'ranks.jsonl')],
    params: (ctx) => ({ limit: ctx.args.limit ?? null }),
    run: async (ctx) => { /* read inputs, write outputs; return a small summary */ },
    parts: [{ file: 'lemmas.jsonl', path: (p) => join(p.build, 'freq', 'ranks.jsonl'), mode: 'merge' }],
    checks: [/* see below */],
  };
  ```
  and add it to `STAGES` in `stages/index.ts` in its place (C2 after `morph`). `parts` with `mode: 'merge'` patch rows of another stage's file by `id` (flags merged one level), so C2 adds `freqRank` and `topForms` without rewriting the morph output; `rows` parts (default) append whole rows (C3 sentences, C4 triggers/patterns/lessons/exercises, C5 scenarios/library). Read big files with `readLines` / `readJsonl` and write with `JsonlWriter`.
- **Add a check**: a `Check` is `{ id: 'c4.trigger-cases', description, run: async (ctx) => { … ctx.issue('…') / ctx.warn('…') } }` in the stage's `checks`. `ctx.rows('lemmas.jsonl')` yields parsed rows with line numbers, `ctx.raw(file)` unparsed rows (use it for `flags.cases`), `await ctx.index()` gives the lemma map (id → key, pos, lemma) and the id sets of patterns, triggers, lessons, exercises and sentences; `ctx.complete` is true on the full build.
- C4: the cases of a preposition are `row.flags.cases` (e.g. `na` → `['acc','loc']`, `s` → `['ins']`, `do` → `['gen']`) in `content/build/morph/lemmas.jsonl` and in `content/build/set/lemmas.jsonl`, read raw.
- Lemma ids: look up by key with `loadRegistry(paths.registry)` / `registry.idOf('mesto|noun|n|1')`, never by position. Only `morph` writes the registry.
- Tests: use `tempRoot()` from `lib/testing.ts` for a throwaway root and `ctx(args)`, and small fixtures beside the stage; never `/mnt/project-files`.
- B2/B3: `ling.form` holds forms with capitals kept; adverb comparatives and adjective comparatives are absent; prepositions, conjunctions and particles have empty tags.
- I2: `pnpm run pipeline load` with `DATABASE_URL` (owner role) loads 1.07 M forms; use `--rank-limit` once C2 has ranks if the database is short of space. The forms table needs about 156 MB.
