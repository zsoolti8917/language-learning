# M4 Declension course and trainer
Status: done

## What was built
Everything lives in `apps/web/src/features/cases/`.

| File | Holds |
|---|---|
| `CourseScreen.tsx` | `/cases`: the nine lessons with status and score, the trainer card, the mastery grid, links to the 16 pattern tables |
| `MasteryGrid.tsx` | Grid of 6 cases × 2 numbers; each cell shows its level as a word, a marker and a tint; a tap opens the four genders in a `Sheet` |
| `LessonScreen.tsx` | `/cases/lesson/$lessonId`: the player with one renderer per step kind (explain with highlighted examples, trigger cards, choice items, typed items with a hint, checkpoint with score and retry), progress saved after each step, completion screen with the added cards |
| `TrainerScreen.tsx` | `/cases/train`: start screen (mode `lesson`/`mixed`/`weak`, size 5/10/20), the session, the summary (improved and still weak buckets, sync state); a running session lives in IndexedDB (`kv` key `cases.trainer.run`) and can be resumed |
| `PatternScreen.tsx` | `/cases/pattern/$patternId`: label, model and everyday word, the table of endings (by number for nouns, by gender for adjectives), notes |
| `ExerciseView.tsx` | One item: sentence with its gap, `AnswerInput` or choice buttons, diagnosis, one retry, link to the pattern table after a pattern mistake |
| `feedback.ts` | `grade(item, typed)`: `diagnoseForm` + `errorTypeFor`, and the feedback as fragments: a hint without the answer (before the retry) and the full sentence with it |
| `grammar.ts` | Pattern id → model word, hard/soft pairs, trigger word from a label, accent slips |
| `attempts.ts` | `makeAttempt`, `dueBatch` (every 5 items and at the end), `sendAttempts` (outbox), applier for `declension.submitAttempts` that keeps the latest mastery in `kv` (`cases.mastery.latest`) |
| `mastery.ts` | Contract thresholds, grid cells, the session summary |
| `progress.ts` | `saveProgress`: direct `PUT`, through the outbox when offline |
| `QueryState.tsx`, `RichText.tsx` | Loading, error, offline and not found states; feedback and lesson markdown with Slovak in `<em lang="sk">` |
| `messages.ts` | All interface text (`defineMessages`) |
| `mocks.ts`, `fixtures.ts`, `mock-data/` | Mock server answers (see below), test fixtures, `build.mjs` that generates `lessons.gen.ts` and `patterns.gen.ts` from the mini dataset |
| `e2e/` | Playwright config (port 5191) and `cases.e2e.ts` |

Feedback examples (exact output):
- *do meste*: hint "That is the locative singular. After *do* comes the genitive." → after the retry "…: *do mesta*."
- *zenam*: "The letters are right, but the accents are not. Watch *ž, á*." → "…: *ženám*."
- *z ulicy*: "*Ulica* is a soft noun. The ending *-y* belongs to hard nouns like *žena*." → "*Ulica* is a soft noun: *z ulice*. …"

## Differences from the specification, and why
- **Mock handlers in tests**: `src/lib/api/client.test.ts` (F6) expects every endpoint of the shared server to replay its contract example, which a feature override breaks. `mocks.ts` therefore exports `handlers = []` under Vitest (`import.meta.env.MODE === 'test'`) and the real ones (`casesHandlers`) in the browser; this feature's tests add them with `server.use`.
- **`mockEndpoint` cannot be used in `features/*/mocks.ts`**: `src/mocks/handlers.ts` imports the feature mocks by eager glob before its own imports are initialised (`ReferenceError: Cannot access … before initialization` at `ENDPOINT_META`). `mocks.ts` has a small local copy of the helper built on `ENDPOINT_META` and `env`.
- **Playwright config inside the feature folder** (`e2e/`), because `e2e-app/playwright.config.ts` only matches F6's files. It builds the mock app into `dist-mock` like F6's, so do not run both at once.
- **Completion cards**: `PUT …/progress` returns only `LessonProgress`. The completion screen lists `GET /notes?kind=case_sentence` notes with source `declension` created from one minute before `completedAt`. When offline it says the cards appear after sync. The mock answers that query only after a completion and otherwise falls through to the default.
- **Diacritics** count as not correct in the trainer and the lesson (state "close", one retry), whatever `strictDiacritics` says; the attempt carries `correct: false`, `clientDiagnosis: 'diacritics'`.
- **Checkpoint**: no retry per item; the score is first-try correct items; pass at `passShare` (default 0.75). A failed checkpoint sends no progress call; "Retry the checkpoint" restarts the step.
- **Lesson start**: resumes at `progress.stepIndex` when `in_progress`, else at step 0. After step *i* the client sends `{ stepIndex: i+1, status: 'in_progress' }`; completion sends `{ stepIndex: last, status: 'completed', score }`. Lesson attempts (`source: 'lesson'`) go out after each exercise step.
- **Grid**: no vocative row. A cell's mastery is the attempt-weighted mean of its genders, with the contract thresholds.
- **Summary**: "improved" means mastery after > before once the server has answered (otherwise ≥ 85 % this session); "still weak" means level `weak` after (otherwise < 60 %). When the server still says `unseen`, this session's score decides. It says "All answers are saved" only when the server has answered for every attempt id of the session.
- **Pattern tables** show endings only, never built forms, because stems change (*mesto → miest*). "Everyday word" in the mock is the most frequent other lemma of the pattern in the mini dataset.
- Trigger word in feedback = the part of `trigger.label` before ` + ` (`do + genitive` → *do*); the phrase *do mesta* is used only when that word stands right before the gap.

## Known gaps and follow ups
- **Requested shared changes (F6):** (1) let `client.test.ts` check the defaults only (`server.resetHandlers(...defaultHandlers)`), so features can override in tests; (2) break the import cycle between `mocks/handlers.ts` and `features/*/mocks.ts` (e.g. move `mockEndpoint` into its own module that does not glob). Other client packages will hit both.
- A completion saved offline waits in the outbox; the completion screen cannot list its cards then. A step saved through the outbox and a later one sent directly could arrive out of order (the server should keep the highest `stepIndex`).
- Trainer mode `lesson` sends the first `in_progress` (else `available`) lesson from the cached course; without the course cached it sends no `lessonId`.
- `mock-data/*.gen.ts` must be rebuilt with `node apps/web/src/features/cases/mock-data/build.mjs` when the mini dataset changes; `tsc` checks them against `LessonDetail` and `PatternDetail`.

## Notes for packages that depend on this one
- I1: start a session from `/cases/train` with the "Start" button (default mode Mixed, 10 items); the answer field is labelled "Fill the gap"; feedback lives in the field's status region. Test ids: `trainer-progress`, `trainer-summary`, `sync-state`, `step-label`, `lesson-complete`, `checkpoint-failed`, `added-cards`; grid cells carry `data-cell="acc.sg"`.
- The applier for `declension.submitAttempts` is registered when the feature loads; it stores the server's mastery under `kv` key `cases.mastery.latest`.
- `grade(item, typed)` and `plainText(fragments)` in `feedback.ts` work on any `ExerciseItem` and can be reused for placement or review explanations.
