# I2 Full content build and load
Status: done with gaps

The full content set is built, checked, reviewed and loaded into a local database (PGlite). Two parts of the specification did not happen. **No request was sent to the API**: by a decision of 2026-11-19 the model's part was written in working sessions, through a new offline mode of the pipeline, for $0. **The set is not loaded into the development database**: that needs the database secret, which this work did not have, so the preview deployment still shows the old content version.

`docs/content-build.md` is the document of the build: how to rebuild, what the set holds against its targets, cost, how each part was checked, the review reports and the database size. This note says what changed in the repository and what the next package must know.

- Tests beside the code:

  - `stages/analysis/analysis.test.ts`: the stage on the mini dataset with PGlite and the offline gateway; `stages/library/library.test.ts`: a row is merged only when the body hash matches, and `validate` checks the analysis against the text.
  - `stages/audit/audit.test.ts`: the sample is the same on every run, an item keeps its request when another leaves the set, verdicts come from the cache, a taught word is shown with the notes of its glosses, the reports.
  - `stages/dict/dict.test.ts`: the editor's list (order, sources, unknown keys reported, a listed lemma is no gap for the fill) and the three import faults.
  - `stages/exercises/exercises.test.ts`: the written gap equals the first answer exactly. `stages/sentences/sentences.test.ts`: exclusions, corrected translations (and a sentence that is in both lists), repeats, the accusative in -ov, the reach of a preposition, personal pronouns, abbreviations, the label of a perfective present form.

## Differences from the specification, and why
- **No paid run.** The specification asks for a dry run, an approval of its cost and a run through the Batch API. The dry runs were made (806 requests, $26.13 and the analysis). The fill itself was written offline, by writers and second readers in working sessions, because there was no API key and the decision of 2026-11-19 was to spend nothing. The pipeline's `--fill live` path is unchanged and still untested against the real API.
- **No load into the development database, no check of the preview deployment.** The set was loaded into an empty PGlite database, where its size was measured. See the first gap below.
- **"The real gateway" of the analysis** is the offline gateway in this build. `analysis --fill live` uses `createGateway` of `@app/ai`.
- **One pull request, not a small one for each fix.** The owner's git flow of 2026-11-17 is one pull request for each build wave. It therefore holds changes outside this package's paths: the analyzer (B3), the eval oracle and reports (I3), the stages of C2 to C5 and four reading texts (C5).
- **A new dependency**: `@app/pipeline` depends on `@app/api` (`tools/pipeline/package.json`, `tsconfig.json`, the lock file). The specification asks for the analyzer "imported from `apps/api`". `pnpm deps:check` passes.
- **More checking than asked.** Every reading the analyzer left open was chosen by two readers apart and the differences settled (1,382 agreed, 14 settled, 17 agreed picks overruled, 34 decided without an earlier pick). Four more readers then read every word of every text. All 1,839 imported dictionary entries of the 5,000 ranked lemmas and of the texts were read against the short dictionary of Slovak (KSSJ), all 1,004 verb entries of the ranked lemmas for the meanings that need `sa` or `si`, and all 2,336 real example sentences with their English and their case labels. The review reports asked for 100 items of each kind once; the pass ran four times, and what the first three rounds found was mended in between (`docs/content-build.md`, "The review reports").
- **Three editor's lists are new.** The import keeps Wiktionary's first three senses in its own order, which put "Sabbath" before "Saturday"; a real sentence can be good Slovak beside English that says something else. The specification has no place for corrections, so `dict` got `overrides.yaml` and `sentences` got `excluded.yaml` and `translations.yaml`. A correction is a row with its reason, never an edit of a generated file or of the import.
- **An analysis row carries the dictionary entries of its lemmas**, as the reader's contract asks. After a change of the dictionary the analysis must be made again (`analysis --all`), see "After a change" in `docs/content-build.md`.
- **The analysis has no price estimate**; its dry run counts requests only (36).
- **Three commit messages carry a wrong number.** `1df3cbe` says the exercise review rejected 58 candidates; it rejected 52 of 3,206. `0be59f0` says 46 wrong reasons are gone on the reading texts; 47 of 50 are mended (43 gone, 4 name the right verb now). `a138d09` says 11 of the 200 entries of the last dictionary reading stand in the editor's own wording; 14 do.
- **A review answer was restored by hand.** The first reviewer of `člen` ("grammatical article") rejected its sentences for the wrong reason. An attempt to overrule the answer in the cache had no effect and was undone: the reviewer's answer and its cache entry were restored, and new sentences went through a second review with the meaning stated. No other cache entry was written by hand.

## Known gaps and follow ups
- **The load into the development database**, then the preview check and the smoke script. With the secret: `DATABASE_URL=… pnpm run pipeline load` from `tools/pipeline` after a rebuild, or `load --dir <folder>` with the built set. The set of this build is not in git (82 MB); a copy is kept in the project's shared files (`content-fill/set-2026-11-20.8.tar.gz`, 8 MB) for whoever does the load, beside the answer files of the fill and the review reports.
- **Nobody has read the content as a person.** Every row has `verified: false`. `content/build/audit/for-you.md` holds 30 items to start with.
- **The review reports end clean on a mended sample.** The fourth round made no remark, but the hundred sentences and the hundred entries it read had been mended three times. The third round is the measure of the rest: 4 small remarks in 100 entries and 2 in 100 sentences, nothing wrong. What the last readers weighed and passed is listed in `docs/content-build.md` ("Round 4") and stands unchanged: four literal translations, three glosses that cover a use only loosely (`pošta`, `nad`, `nielen`), three entries (`prehliadka`, `doktor`, `priestor`).
- **The written glosses were read one by one only where they are verbs.** The 3,246 written glosses had no second reader of their own as the imported entries had; the 869 verb entries among them were read for `sa` and `si`, and the review reports sample the top 3,000 lemmas, written and imported alike. Two of the four entries the third round found wanting were written ones (`k`, `orgán`: a missing meaning, a gloss that needs a note), so a reading of all of them would find more of that kind.
- **The reader does not show the note of a gloss.** An analysis row and the reader's contract carry the gloss texts only, so a meaning marked "with sa" appears in the reader without its mark (`hrať`: "to play; to play, to play with"). The word's card shows the notes.
- **`video` (adjective)** has no sentence. The right fix is in the morphology: it is no word of its own.
- **Faults of the morphology** that the texts and sentences showed; none is patched, the set follows the data:
  - `Košice` is a neuter noun in the data (it is feminine), `Piešťany` feminine (masculine), `dunčo` inanimate.
  - The plural of an animal noun is a second, inanimate lemma (`pes`: `psy`, `psov`): 526 such pairs, three of them with a rank (`pes`, `kôň`, `vták`). Their entries say what the label means; the label itself still stands on the card and in the reader. The data has `psov` as a genitive only and lists `psi` as an accusative. The sentences stage adds the accusative reading; the analyzer and the exercises do not.
  - `odfotiť` is marked imperfective (it is perfective). The most used forms of the verb `lepšiť` are forms of the adjective `lepší`. `metro` has no rank, so `metra` is read as a form of `meter`. `čína` ("Chinese food", rank 3,837) carries the frequency of the country `Čína`, which has no rank.
  - A negated verb is a lemma of its own (`nemať`), so the reader shows `nemám` under `nemať` and its card has no link to `mať`.
  - Comparatives are missing (`lepšie` is unknown as a form of `dobre`), and so are `e-mail`, `toto` and `tamto` as the reader would want them. `cesto` has a rank that the texts suggest is too low.
- **Labels of the treebank can mislead.** A treebank sentence is shown with the reading its annotators gave: quantity words in adverb use are numerals there (`trochu`, `najviac`), `ho` for `pohár` is a neuter, and `jej` after `dotknúť sa` was an accusative (that sentence is excluded). The reading of every real sentence caught what a reader could see; the labels were not checked against a second source.
- **"with sa when it has no object" is a rule of thumb.** 68 notes of the verb entries use it (`hýbať`: `nehýb sa` with `sa`, `hýbať rukou` without). It fails where the plain verb can stand without an object too (`otvárať`: obchod otvára o ôsmej); the entries where a reader saw that say "with sa when the thing itself opens" and give an example.
- **Cards under an adverb entry that show a quantity use** (`viac`, `dosť` with a genitive): the sentence is right, the entry says "more" as an adverb only.
- **Three rule meanings are too narrow** for a `choice_meaning` exercise: `prep-o-loc`, `prep-o-acc` and `prep-na-acc` ("onto, to (a place or an event)") where a verb governs the preposition (`čakať na`, `myslieť na`).
- **The label of a perfective present form for the learner.** The pipeline now says "present form of a perfective verb (future meaning)" where it puts a tag into words for writers and auditors (`describeTag`). The stored rows carry the tag, not the words, and the app keeps a verb tag opaque in the first release (`packages/ling/src/tags.ts`). Whoever writes its label must say the same: `oceníte` is no present tense.
- **Limits of the verb rule** (64 wrong reasons in 3,692 on the treebank): the clause is cut at the last conjunction between two verbs; a parenthesis between an auxiliary and its past form; an infinitive as the subject (`Bavilo ma písať`); `mať` with a noun and an infinitive; `byť` with an instrumental of means; accusatives joined after a preposition. Three wrong reasons are left in the texts (`lib-006`, `lib-011`).
- **The tokens of an example sentence are not disambiguated**: a token gets the lemma of its first reading. Only the linked word is checked. The reader never shows these tokens; anything that will must run the analyzer first.
- **The review request of a sentence shows no meaning of the lemma**, which misled one reviewer (`člen`). The audit request shows it. `content.review` should too, with a new prompt version.
- **Unused rows**: 30 translations of treebank sentences that are no longer chosen stay in `sentences.jsonl`; the stage ignores them.
- **The live path** of every model stage has still not met the API.

## Notes for packages that depend on this one
- **Whoever loads the set (F8, I5)**: the load writes a new content version (`2026-11-20.N`). 200.6 MB of content fit the 500 MB plan without `--rank-limit`. The first load of 1.07 M forms takes minutes on a remote database.
- **B4 (reader)**: the twelve library texts arrive analysed (`library.jsonl` has `analysis` and `lemmaCounts`), 2,512 words, none guessed. A text a learner pastes still goes through the model.
- **B3 (analyzer)**: `rules.ts` grew from the readings of real texts; `docs/handoff/B3.md` describes the older rules. The rule tests name the sentence behind each change.
- **I3 (evals)**: the oracle answers a word that stands twice once for each place. The reports are regenerated; no live number exists yet.
- **Changing content later**: a dictionary entry is corrected in `overrides.yaml`, never in `glosses.jsonl` or in the import. A wrong generated row is removed from its file in `content/generated/` and the stage asks for it again. The table "After a change" in `docs/content-build.md` says which stages follow.
- **Filling without the API again**: `--fill offline` on any model stage, the guides in `tools/pipeline/src/offline/guides/`, and the four rules in `docs/content-build.md`. Never run a stage while its writers work.
- **Licences**: written content is `CC BY 4.0` with `source: generated` or `manual`; Tatoeba and treebank rows keep their own, see `content/SOURCES.md`.
