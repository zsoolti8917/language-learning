# M1 Account, onboarding, settings and Today
Status: done with gaps

## What was built
All inside `apps/web/src/features/account/` and `apps/web/src/features/today/`. The export names of F6's placeholders are unchanged, and every screen keeps its shell title (`screens.*`) as its `h1`.

| Path | Holds |
|---|---|
| `account/LoginScreen.tsx` | Email and password, links to sign up and reset, the one tap dev login (`dev.signIn`), then `redirect ?? '/'` |
| `account/SignupScreen.tsx` | Email and a new password (8 or more characters), `signUp`, then `/verify` |
| `account/VerifyScreen.tsx` | The six digit code: one field with `autocomplete="one-time-code"`, digits only, paste support (`"123 456"` becomes `123456`), sends itself on the sixth digit; resend waits 60 s with a countdown; dev hint with the code `123456` |
| `account/ResetScreen.tsx` | Email, then code and new password: `requestPasswordReset` → `verifyCode(…, 'recovery')` → `updatePassword` (after a refused password only the password is asked again) |
| `account/OnboardingScreen.tsx` | Name, minutes per day (5/10/15/30/60 → daily caps), detected time zone (editable, checked with `Intl`). One `PATCH /me` with `displayName`, `timezone`, `dailyNewLimit`, `dailyReviewLimit`, `settings: { …settings, minutesPerDay, onboardedAt }`, then `/` |
| `account/{validation,pending,code,parts,profile}.ts(x)` | Form checks and error texts, the pending code in `sessionStorage` (`app.pendingCode`), `CodeField`, `ResendButton`, `AuthScreen`, `ChoiceGroup` (radio group made of `Button`), `useProfile`, `useUpdateProfile` (stores the answer in the query cache and in `kv` `profile`) |
| `account/mocks.ts` | Mock `PATCH /me` that remembers the profile in `localStorage['m1.mockProfile']`; `GET /me` answers it when present, else falls through to the example; `DELETE /me` clears it |
| `today/TodayScreen.tsx` | `GET /today` + `GET /me`: first run card → `/placement` (when `placementDoneAt` is null), "all done" state, reviews with Start, continue reading, next lesson, weak cases (`CaseBadge`), tutor suggestion, word band ring; settings link; loading, error, offline states |
| `today/SettingsScreen.tsx` | Caps, strict accents (switch), target retention, theme (system, light, dark), export (JSON download), sign out, deletion that asks twice (sheet, two steps), link to About. Each change sends `PATCH /me` with only the changed fields; disabled offline |
| `today/AboutScreen.tsx` | App version (`VITE_APP_VERSION`), server and content version (`GET /health`), the six sources of docs/architecture.md "Licences" |
| `today/AppNotices.tsx` | Offline indicator, update prompt, one time iOS install hint (lib/pwa hooks), on Today and Settings |
| `today/theme.ts` | `settings.theme` → `data-theme` on `<html>`, also kept in `localStorage['app.theme']` |
| `today/fixtures.ts`, `today/mocks.ts` | Three `Today` variants (fresh, middle = contract example, done); the mock picks one from `localStorage['m1.mockToday']`, or `fresh` for a stored mock profile without placement |
| `*/messages.ts` | All interface text (`defineMessages`) |
| `account/e2e/playwright.config.ts`, `account/e2e/*.e2e.ts`, `today/e2e/today.e2e.ts` | Playwright at 390 x 844 on a mock build (port 5191, `M1_E2E_PORT` overrides) |

## Differences from the specification, and why
- The route table has no search params for `/verify`, so the email and purpose of the pending code travel in `sessionStorage` (`app.pendingCode`). Without one, `/verify` points back to sign up and sign in.
- Verify sends the learner to `/`; the guard sends a first run to onboarding. Onboarding then goes to Today, whose first run card leads to `/placement` (the contract's `Today` has no first run flag; Today uses `profile.placementDoneAt`).
- The design system has no radio group, switch or select: `ChoiceGroup` (radio semantics, arrow keys) and the strict accents switch are made of `Button`; the time zone is a text field checked against `Intl`.
- Theme lives in `profile.settings.theme` (no column for it) and is applied by Today and Settings when they mount, since the shell has no boot hook for it.
- The app version comes from `VITE_APP_VERSION`, which nothing sets yet; About shows "Not known" until then.
- Playwright config lives in `features/account/e2e/` because F6's config matches only its own files.
- Today and Settings import `account/profile.ts` and `account/parts.tsx` (both folders are M1's).

## Known gaps and follow ups
- Requested shared changes (not made): (1) the shell applies `localStorage['app.theme']` before the first paint (main.tsx or index.html) so non-Today deep links get the theme; (2) `vite.config.ts` defines `VITE_APP_VERSION` (for example from `package.json` or the git sha); (3) the offline indicator and update prompt belong in `TabLayout` so every tab shows them; M1 renders them only on Today and Settings; (4) optionally a `/verify` `email` search param in the route table.
- Settings changes are online only (disabled offline), not queued in the outbox.
- `vaul` keeps the closed sheet mounted in jsdom; tests check `data-state` instead.
- Not tried against real Supabase or on a real iPhone.

## Notes for packages that depend on this one
- First run ends with `settings.onboardedAt`; `settings.minutesPerDay` and `settings.theme` are also set by M1. A `PATCH /me` that changes `settings` must send the whole object (`withSetting(profile, key, value)` in `account/profile.ts`).
- The mock server's `PATCH /me` now remembers its answer in `localStorage['m1.mockProfile']` (browser and tests; `src/test/setup.ts` clears localStorage after each test).
- I1: `/today` counts are shown as `review.due`, `review.new`, `review.learning`; "all done" means all three are 0.
