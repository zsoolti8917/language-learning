# F5 API skeleton
Status: done

## What was built
A running API (`apps/api`) in which all 45 endpoints answer with their contract example, every port has a stand in with a shared test suite, and the first version of `packages/ai` (gateway types, mock gateway, gateway suite, `createGateway`, six prompt folders).

| Piece | Where |

| Route helper: token check, profile creation, validation of params/query/body, response validation in local mode and tests | `platform/route.ts` (`route`, `mountRoutes`, `HandlerContext`) |
| Token check: Supabase keys through jose, or `Bearer dev:<uuid>` | `platform/auth.ts` |
| Errors in the contract shape | `platform/errors.ts` (`ApiError`, `notFound()`, `conflict()`, `rateLimited()`, `validationFailed()`, `toApiError`) |

## How to run and test it
- `pnpm dev` starts the API on `http://localhost:8787/api/v1` (PGlite in `.local/pgdata`, migrations, mini dataset, dev login, mock gateway). `curl localhost:8787/api/v1/health` → `{"ok":true,"version":"0.1.0","contentVersion":"2026-11-17.1"}`. Delete `.local/` to reset. `PORT` changes the port.
- `pnpm test --filter api`, `pnpm test --filter ai`, `pnpm check`.

Tests that prove the done list:
- `src/server.test.ts`: the Node server in local mode over real HTTP: health with version and content version, dev login, restart on the same data folder.
- `src/app.test.ts`: all 45 endpoints called as a dev user with their example request, every response parses (the stream event by event); 401 in the error shape without a token; 400 with `details.fields` for body, path and query; malformed JSON; body over 256 KB; error mapping (ApiError, budget, upstream, internal without internals, response not matching the contract); profile created once; `createTestDb({ content: 'mini' })` holds 72 lemmas.
- `src/platform/auth.test.ts`: ES256 key set made locally: valid, expired, wrong issuer, wrong signature, non-uuid `sub`; and the app in Supabase mode.
- `src/platform/config.test.ts`: guards; spawns `server.ts --local` with `APP_ENV=production` and sees it exit 1.
- `src/platform/usage.test.ts`: a row counts toward that learner only; the spend starts again at the learner's day start (New York learner, fixed clock); the mock gateway stops at the budget and resumes next learner day; `learnerDay` incl. summer time.
- `src/testing/stand-ins.test.ts`: each stand in passes its port suite. `packages/ai/src/mock.test.ts`: the mock passes the gateway suite.

## Differences from the specification, and why
- **Defaults of the config are the production ones** (`DB_MODE=postgres`, `AUTH_MODE=supabase`, `AI_MODE=anthropic`); local mode comes from `server.ts --local` (`pnpm dev`), so a forgotten variable never turns on the dev login. Values already in the environment win over the local defaults.
- **Extra server variables** (not in `.env.example`, which is F1's): `PGLITE_DIR` (default `<repo>/.local/pgdata` with `--local`, in memory otherwise), `PORT` (8787), `CONTENT_DIR` (local content folder, default the mini dataset), `VALIDATE_RESPONSES` (default true when `APP_ENV=local`).
- **Local database preparation lives in `src/testing/local.ts`**: the dependency check lets only test code (files under `testing/`) import `@app/testkit`, and the mini dataset is there. `runtime.ts` imports it dynamically only in pglite mode.
- **A body over 256 KB** answers 400 `validation_failed` (`details.fields.body`): the error table has no 413 code.
- **The version** that health reports is `API_VERSION` in `platform/config.ts` (0.1.0, as the example), not `package.json` (0.0.0).
- **Port details the docs left open**: `lookupForms` is keyed by `lookupKey(form)` = `foldAscii` (lower case, no accents), holds a key for every input, candidates of a key are all forms folding to it with exact matches first. `ensureGlosses` takes an optional `ctx.userId` (the gateway needs a learner for budget and usage). `setLemmaStatus` takes `LemmaStatusSource`. Input types `WordNoteInput`, `PhraseNoteInput`, `CaseSentenceNoteInput` (id optional: generated when omitted) and `AttemptRecord` (mirrors `app.attempt`, `occurredAt` ISO string) are in `ports.ts`.
- **Gateway config** names the two functions `spendToday(userId) → { spentUsd, resetsAt }` and `recordUsage(row)`. Errors are `AiGatewayError` with `code` `budget_exceeded | upstream_failed | refused | truncated`; output not matching the schema is `upstream_failed` (`details.reason: 'invalid_output'`).
- **`PromptFolder.mock`**: a prompt folder may define the mock answer of its route for local mode; only `tutor.reply` has one (`Ideš dnes do mesta?`, the F2 example line).
- `apps/api/vitest.config.ts` was added (project name `@app/api`, longer hook timeouts for PGlite under load).
- The root `dev` script was not changed: it already runs `pnpm --filter @app/api run dev`. F6 adds the client.

### A handler
```ts
// modules/notes/routes.ts
import { route } from '../../platform/route';
import * as service from './service';
export const routes = [
  route('notes.get', ({ params, withUser, ports }) =>
    withUser((tx) => service.getNote(tx, ports, params.id))),   // returns ResponseOf<'notes.get'>
  route('notes.delete', async ({ params, withUser }) => {
    await withUser((tx) => service.deleteNote(tx, params.id));
    return undefined;                                            // 204
  }),
];
```
`HandlerContext`: `params`, `query`, `body` (validated, typed `RequestOutput<N>`), `userId`, `withUser(fn)`, `ports`, `deps` (`config`, `database`, `clock`, `ids`, `ai`, `background`, `profiles`, `usage`), `signal` (client gone), `c` (Hono context). Return the body (the status comes from the endpoint table), `undefined` for 204, or a `Response` (streams: `sseResponse(async (send) => …, { signal })`). Throw `ApiError` helpers from `platform/errors.ts` (`notFound()`, `conflict(msg)`, `rateLimited(msg, seconds)`, `validationFailed({ 'body.x': '…' })`); an `AiGatewayError` maps itself (budget → 429 with `resetsAt`, others → 502). Responses are checked against the contract in local mode and tests: a mismatch is a 500 that names the fields.

### Ports and transactions
- `withUser` runs the whole function in one transaction as the learner (RLS on). Pass `tx` to services and port methods. **No model or network call inside** — call `ports.analyzer`, `ports.dictionary.ensureGlosses` and `deps.ai` between transactions.
- `withSystem` (`deps.database.withSystem`) is for reference data and glosses only.
- Port methods taking `tx` read the learner with `currentUserId(tx)` (`platform/tx.ts`).
- A factory gets `PortContext` (`config`, `database`, `clock`, `ids`, `ai`, `background`, `ports`). Use other ports only inside methods (`ctx.ports.morphology`), never while constructing.
- Time: `deps.clock.now()`. Ids: `deps.ids.uuid()` (UUID v7). Learner day: `learnerDay(now, profile.timezone, profile.dayStartHour)` → `{ start, end }`.
- Background: `deps.background.runInBackground(promise)`; tests `await t.drain()`.
- `DELETE /me` (B7): call `deps.profiles.forget(userId)` after deleting the rows, so the next call recreates the profile.

### Port suites
`apps/api/src/testing/suites/{morphology,dictionary,notes,attempts,analyzer}.ts` export `run<Port>Suite(name, make, shared?)`. `make(ctx)` builds the port from a `PortContext` over a test database with the mini dataset and the mock gateway. Your real port must pass:
```ts
// modules/lexicon/port.test.ts
import { runMorphologySuite } from '../../testing/suites/morphology';
import { createMorphologyPort } from './port';
runMorphologySuite('real', (ctx) => createMorphologyPort(ctx));
```
`suites/notes.ts` also exports `BRATA_CASE_SENTENCE` and `V_MESTE_PHRASE`. Several suites in one file can share one database (`stand-ins.test.ts` shows how).

### `apps/api/src/testing`
- `createTestApp(opts?)` → `{ app, deps, db, ports, gateway, clock, as(id?), anon, drain(), close() }`. Options: `db` (share a `createTestDb` one), `content` (`'mini'` default, `null` for none), `now`, `ids`, `ports` (override single ports, e.g. a failing analyzer), `config`, `auth`. About 2 s; create one per file in `beforeAll`.
- `t.as()` is a new learner (dev login); `t.as(id)` a given one; `t.anon` has no token. Clients have `get/post/put/patch/delete(path, body)` with paths below `/api/v1`, and `call(name, { params, query, body })`. Responses: `{ status, headers, body, text }`.
- `t.clock` is a `FixedClock` (`set`, `advance`), default `2026-11-17T08:30:00Z`. `t.db.factory.*` and `t.db.resetApp()` come from F3.
- Recorders: with the stand ins in place, `t.ports.notes as NotesRecorder` (from `testing/recorders.ts`) (`notes`, `statusCalls`, `statusOf(userId, lemmaId)`) and `t.ports.attempts as AttemptsRecorder` (`attempts`). They need a real `withUser` transaction.
- `createSequentialIds()`, `createFixedClock()` in `platform/clock.ts`; `parseSse(text)` in `platform/sse.ts`.

### Gateway mock (`@app/ai`)
```ts
t.gateway.script('reader.translate', { data: { en: 'I live in town.' }, usage: { costUsd: 0.002 } });
t.gateway.script('tutor.reply', { text: ['S kým ', 'ideš do kina?'] });       // stream pieces
t.gateway.script('tutor.analyze', { error: 'refused' });                         // or truncated, upstream_failed
t.gateway.respond('reader.gloss', (call) => ({ data: … }));                      // when the queue is empty
t.gateway.calls; t.gateway.callsFor('reader.gloss'); t.gateway.pending(); t.gateway.reset();
```
Each call checks the learner's budget first (`spendToday` ≥ `AI_DAILY_BUDGET_USD` → `AiGatewayError('budget_exceeded', …, { resetsAt })`, no model call), takes the next scripted answer, parses `data` with the request's schema, and writes a usage row through `recordUsage` (status `ok`, `refused`, `truncated` or `error`). Unscripted calls fail with `upstream_failed`. Default usage: tokens from text length, cost 0. Standalone: `createMockGateway(opts)`; with prompt folder defaults: `createConfiguredMock(config)`.
