# C2 Frequency ranks and dictionary
Status: done with gaps

## What was built
The stages `freq` and `dict`, the batch runner and the prompt of the route `content.glosses`, in `tools/pipeline/src/`.

| Piece | Where | Does |
|---|---|---|

| Stage options | `model/options.ts` | `FILL_OPTIONS` (`--fill none\|dry-run\|mock\|live`, `--max-spend <usd>`), `runOptionsOf(ctx)`, `modelCacheDir(paths, mode)` |
| `content.glosses` v1 | `model/prompts/content-glosses.ts` | System prompt, `GlossAnswerSchema` (`{ items: [{ key, glosses: 1–3 strings of ≤ 60 characters }] }`), a check that every key is answered once, 25 words per request, effort low, a mock answer `[mock] <lemma>` |

### Ranking
1. **Web score**: the sum of the ARF of every Araneum word form + tag row the morphology assigns to the lemma: the form is one of its forms, and the row's SNK tag, mapped with C1's `mapSnk`, is one of that form's tags (`x` + case for pronouns without agreement). A capitalised row falls back to lower case. A row that fits several lemmas (*je*: byť and jesť) is split in proportion to the lemmas' ARF in the Araneum lemma list.
2. **Subtitle score**: each OpenSubtitles word count, split over the lemmas of that spelling as the web split it (else by the lemmas' web scores).
3. Each list is ranked on its own (a lemma missing from a list gets the list's length + 1). **score = 0.6 · ln(web rank) + 0.4 · ln(subtitle rank)**, a weighted geometric mean of the ranks; the lowest score is rank 1, ties by web rank, then id.
4. Ranked are lemmas that are not retired, not proper names, and not of part of speech `other`, except the reflexive `sa` and `si`.
5. **Top forms**: the four `(form, tag)` pairs with the largest web ARF, each with its share of the lemma's web total, rounded down to three decimals (so they never sum above 1). A lemma with no web rows takes its subtitle forms.

## How to run and test it
- `pnpm test --filter pipeline` or `pnpm check` (passes). The C2 tests take about 3 s.
- Full run: `pnpm run pipeline fetch --source araneum-arf,frequencywords,kaikki-wiktionary` → `morph` → `freq` → `dict` (→ `dict --fill dry-run` for the estimate) → `validate`.
- Tests prove each item of "Done when":
  - Top 30: `freq.test.ts` runs `freq` on the sample and holds the full run's top 30 as a snapshot. The sample is built so that ranks 1 to 67, scores included, equal the full run (checked once by comparing `ranks.tsv`).
  - Fill on a sample: `dict.test.ts` runs `dict --fill mock --sample 10`, then the whole sample: every ranked lemma has a sense, every row from `glosses.jsonl` enters `senses.jsonl` with `source: generated` and `verified: false`, Wiktionary rows carry `wiktionary`; the assembled set (morph + freq + dict) passes `validate`, including `freq.top-forms` and `dict.glosses`.
  - Top forms: the sample's every top form is checked against `forms.jsonl` and its tag, the sum of shares ≤ 1; `freq.top-forms` fails a sum above 1, an unknown form, a wrong tag and a repeated rank.
  - Runner, mock mode (`model/runner.test.ts`): a cached request is not sent again (the mock client's request log), identical jobs are one request, an answer that breaks the schema is rejected with `schema: gloss: …`, not cached, and asked again on the next run; a failed task check, non-JSON, `max_tokens`, `refusal`, `errored` and `expired` are rejected and reported. Also: the dry run sends nothing and prints count and estimate; a live run estimated above $5 throws `SpendLimitError` before any request unless `maxSpendUsd` is raised; a batch left by a crashed run is collected, not resent; large runs split into batches; a mock answer is never reused by a dry or live run.

## Differences from the specification, and why
- **The `content.glosses` prompt lives in `tools/pipeline/src/model/prompts/`, not `packages/ai/prompts/`.** `AiRoute` in contracts and `PromptFolder.route` hold only the live routes, and the package owns `model/`. The batch runner does not use the gateway.
- **Validate fails on the full build until the paid fill**: `dict.glosses` makes a ranked lemma without a gloss an issue in a complete build for ranks up to 3,000 (I2's target), a warning beyond. Today that is 1,710 issues in one message. For development builds use `dict --fill mock`.
- **One C1 file changed**: `stages/validate/validate.test.ts` ran validate with every registered stage after running only morph. With `dict` registered, its `senses.jsonl` part is missing there and assembly stops ("run its stage first"), so the test now passes the stages up to morph explicitly (3 lines). C3 to C5 would hit the same. `stages/index.ts` registers `freq` and `dict`, as C1's note asks.
- **No `content/generated/glosses.jsonl` is committed**: no model fill ran (no key). `dict` reads it when it exists. A mock fill writes `content/build/dict/glosses.mock.jsonl` and caches in `content/build/model-cache-mock/`, never in git or in the real cache.
- Wiktionary senses get `verified: false` like everything not checked by a person; the source says where they came from. The mini dataset's 87 manual senses are not merged into the full build.
- Proper names are not ranked (no *Slovensko*, *Bratislava*); the ranking is for vocabulary.
- Negated verbs are lemmas of their own in SNK and so ranked (*nebyť* 60, *nemať* 66). *aj*, *tak* and a few others are several lemmas (particle, conjunction, adverb) and ranked apart, as SNK has them.
- Top forms are `(form, tag)` pairs: *to* appears as `s1n` and `s4n` of *ten*. That matches `TopForm` in contracts.
- Shortened glosses move a parenthesised explanation into `note` ("to make", note "to create from a certain material"); a qualifier like "(with locative)" wins over it.

## Known gaps and follow ups
- **No request has reached the API.** Live mode is exercised only through the mock client; the first live run should be a `--sample 25` fill, read by a person, before the full one.
- The cost estimate counts bytes, not tokens; I2 can calibrate it from the usage the first live batch reports (`actualUsd` in the report).
- Wiktionary covers only 58.7 % of the top 1,000, so about 3,200 of 5,000 glosses will be model written. A second review pass (`content.review`) is I2's.
- `freq`'s fingerprint covers its own folder and `lib/`, not `stages/morph/snk.ts`, whose `mapSnk` it uses: after changing the tag mapping, run `freq --force`.
- The prior that splits ambiguous rows comes from the lemma list by spelling and part of speech, so two noun lemmas of one spelling but different gender (rare) get the same prior.
- `src/index.ts` (C1) does not re-export `model/`; stages import it by relative path.

## Notes for packages that depend on this one
- **Ranks**: `freqRank` (1 = most common, 1 to 5,000) and `topForms` are in `content/build/set/lemmas.jsonl` after validate, and in `content/build/freq/lemmas.jsonl` (only ranked lemmas) right after `freq`. A stage that needs ranks lists `freq/lemmas.jsonl` among its inputs. `ranks.tsv` has the best 10,000 with both source ranks. C3's "within the 3,000 most common" is `freqRank <= 3000`; C5's 2,000 likewise.
- **Glosses**: `content/build/dict/senses.jsonl` (`source` wiktionary or generated).
- **Using the batch runner (C3, C4, C5, I2)**:
  ```ts
  import { FILL_OPTIONS, runOptionsOf } from '../../model/options';
  import { type BatchTask, runBatch } from '../../model/runner';
  const sentencesTask: BatchTask<In, Out> = {
    route: 'content.sentences', promptVersion: 1, effort: 'medium', maxTokens: 8000,
    system: SYSTEM,                 // stable: no dates, ids or per-request values
    schema: OutSchema,              // zod; sent as the output JSON schema, parsed on return
    user: (input) => JSON.stringify(input),
    check: (input, out) => [],      // rule checks: return problems, an answer with any is rejected
    estimateOutputTokens: (input) => 400,
    mock: (input) => ({ ... }),     // what --fill mock answers
  };
  // In the stage: options: { ...FILL_OPTIONS, ... }, and in run():
  const options = runOptionsOf(ctx);            // null when --fill is none
  if (options) {
    const out = await runBatch(sentencesTask, jobs, options);  // jobs: [{ id, input }]
    // out.results: [{ id, input, output, hash, cached }]; out.failures: [{ id, hash, reason }]
    // out.estimate (requests, tokens, usd, worstUsd); out.sent; out.actualUsd
  }
  ```
  Put the prompt in `model/prompts/<route>.ts` (ask C2's owner, or add your own file there: it is the shared prompt folder of the pipeline). Group several items per request when they share the prompt, as `content.glosses` does: the request is the unit of caching. Write accepted answers to your file in `content/generated/` and skip items already there before you build jobs, so reruns and a restarted I2 run send nothing twice. Add `at: ctx.now()` to `params` for `dry-run` and `live`, as `dict` does, so those modes always run. Never put the mock answer into `content/generated/`.
- **Safety**: `--fill dry-run` prints `N requests for M jobs, C cached, S to send; estimate … $X at batch prices (at most $Y)`. `--fill live` throws `SpendLimitError` when $X is above $5 unless `--max-spend <usd>` is given; check the dry run first. Credentials come from the SDK's own lookup (`ANTHROPIC_API_KEY`, …); the pipeline never reads or logs them. Live polling is every 60 s; a batch id is written to `content/build/model-cache/<route>/pending/` until collected, so an interrupted run resumes it instead of paying again.
- Every request uses `claude-opus-5-5` with adaptive thinking left on (it cannot be turned off) and the effort of the task; no `temperature`, no forced tool use, no `fallbacks` (the Batches API rejects them).
- **I2**: run `dict --fill dry-run`, approve, then `dict --fill live` (expected about $1.70); `content/generated/glosses.jsonl` is then committed. `load --rank-limit 5000` now keeps the ranked lemmas.
