# C5 Scenarios and starter library
Status: done with gaps

## What was built
The stages `scenarios` and `library` in `tools/pipeline/src/stages/`, twelve authored scenarios in `content/authored/scenarios/` and twelve authored texts in `content/authored/library/`.

| Piece | Where | Does |
|---|---|---|
| Scenarios | `content/authored/scenarios/<id>.yaml` | One YAML file per scenario with every field of `ScenarioRow` (camelCase, as in `scenarios.jsonl`). 8 goal based: `scn-cafe-order`, `scn-asking-way`, `scn-doctor`, `scn-groceries`, `scn-flat-rent` (B1), `scn-train-station`, `scn-neighbour`, `scn-weekend`. 4 case coach sets: `scn-coach-acc`, `scn-coach-na-v` (na and v, locative against accusative), `scn-coach-gen` (do, z, od), `scn-coach-ins` (s). 3 or 4 success criteria and 6 vocabulary hints each |
| Texts | `content/authored/library/lib-001.md` … `lib-012.md` | Front matter (`id`, `ord`, `title`, `level`, `topic`, optional `source`, `license`, default `authored`, `CC BY 4.0`) and the Slovak body; paragraphs split by an empty line. 8 A2 texts of 163 to 208 words (home, shopping, work, weekend, doctor, train, family, seasons), 4 B1 texts of 240 to 255 words (neighbours, grandmother's halušky, cycling to work, Christmas). Written for this project |
| `scenarios` | `stages/scenarios/index.ts`, `triggers.ts` | Parses the YAML (strict `ScenarioRowSchema`, file name = id), checks the rules and writes `content/build/scenarios/scenarios.jsonl` (a `rows` part of `scenarios.jsonl`) and `report.md` / `report.json`. Fails on any problem. Checks `scenarios.rules`, `scenarios.slovak` |
| Trigger rules | `stages/scenarios/triggers.ts` | Id convention `^(prep\|verb\|num\|quant\|q\|adj\|noun\|fn)(-[a-z0-9]+)+$`; when the trigger is known, the prefix matches its kind and a case suffix (`-acc`) matches its case. Known triggers: the mini dataset's `triggers.jsonl`, then every object with a trigger-like `id` in C4's `content/authored/triggers/**/*.yaml` (only `id`, `kind`, `case` are read). Every target trigger must be known and govern one of the scenario's target cases |
| `library` | `stages/library/index.ts`, `authored.ts`, `vocab.ts`, `setvocab.ts` | Reads the texts, tokenizes with `@app/ling` `tokenize`, looks every word up among the morph forms (as written, and in lower case when it has a capital), counts tokens and lemmas, measures the vocabulary profile, and writes `content/build/library/library.jsonl` (a `rows` part of `library.jsonl`; no `analysis`, no `lemmaCounts`) and `report.md` / `report.json`. Fails on an unknown word, a text outside 150 to 400 words, a repeated id or ord, or an A2 text below 90 %. Checks `library.texts`, `library.vocabulary` |
| Review pass | `stages/library/review.ts` | Route `content.review` v1 through C2's `runBatch`: one text per request, effort medium, answer `{ verdict: ok\|revise, level, problems: [{ quote, issue, fix }] }`; the task check rejects a quote that is not in the text and a `revise` without a problem. Answers go to `content/generated/library-reviews.jsonl` (live) or `content/build/library/reviews.mock.jsonl` (mock), keyed by text id and the sha256 of its body |
| Fixture | `stages/library/fixtures/`, `sample.ts` | The real morphology and ranks cut to the 1,017 lemmas and 2,670 forms the authored files need, plus the mini trigger lemmas (`make-fixture.py` regenerates it from `content/build`); `seedLibrarySample(paths)` places them, the authored folders and the mini triggers in a temporary root |

**Vocabulary profile.** For each word token: no reading → unknown; every reading a proper name (`flags.proper`) → a name, left out of the share; else the best ranked reading counts, and the token is within when that rank is ≤ 2,000. Share = within / (known words that are not only a name).

**Review mark.** Each row of `library.jsonl` carries `review: { status: 'reviewed', verdict, level, problems, model, promptVersion, mock? }` when a review of its current body exists, else `review: { status: 'unreviewed' }`. An edited text loses its review.

## How to run and test it
- `pnpm test --filter pipeline` or `pnpm check` (passes). C5's 21 tests take about 2 s.
- `pnpm run pipeline scenarios`; `pnpm run pipeline library [--fill none|dry-run|mock|live]` (needs `morph` and `freq` outputs); then `validate`.
- Tests prove each item of "Done when":
  - `validate` passes for both files: `library.test.ts` assembles morph + freq (fixture) + the mini triggers + scenarios + library (after a mock review pass) and runs the validate stage; the report shows 0 issues for `library.texts`, `library.vocabulary`, `scenarios.rules`, `scenarios.slovak`. Another test breaks a copy of that set (unknown word, 2 word text, unmarked text, trigger with a case outside the targets, malformed trigger id) and gets each issue.
  - Target triggers: `scenarios.test.ts` checks every trigger of the 12 scenarios against the convention and the mini `triggers.jsonl`, with its case among the target cases; a trigger found only in a C4 style YAML is accepted, an unknown one fails the stage; unit tests for the convention, kind prefix and case suffix.
  - 90 % within the top 2,000: `library.test.ts` runs the stage on the fixture (the real ranks) and checks every A2 text's share; a text with rare words appended fails with the share message, a misspelled word fails as not a known form.
  - Reviewed or unreviewed: rows are `unreviewed` without a fill; a dry run sends nothing; a mock pass marks all 12 `reviewed` (with `mock: true`) and a rerun asks for nothing; an edited text goes back to `unreviewed`.
- Full data (recorded, this container; raw sources and the morph/freq/dict build copied from C2's run): `scenarios` 0.1 s, `library` 1.7 s. `validate` with `dict --fill mock`, `library --fill mock` and the mini triggers standing in for C4's `triggers.jsonl` **passes** (100,681 lemmas, 1,072,858 forms, 12,107 senses, 22 triggers, 12 scenarios, 12 texts). ## Differences from the specification, and why
- **The review status is an extra key of `library.jsonl`, not a database column.** `LibraryRowSchema` and `ling.library_text` have no such field; zod strips the key when the loader parses the row, so the database never sees it. A shared surface PR can add a `reviewed` column if the app should show it.
- **The `content.review` prompt lives in `stages/library/review.ts`**, inside C5's paths, not in `model/prompts/` (C2's folder). It is the library's review; C3/C4 may want their own `content.review` tasks with other inputs.
- **Reviews are stored in `content/generated/library-reviews.jsonl`**, which the Owns line does not name; no such file exists yet (no live run). Mock reviews stay in `content/build/`.
- **Files outside the owned paths**: `stages/index.ts` registers `scenarios` and `library` (as C1's note asks); `stages/validate/validate.test.ts` holds the mini dataset to the checks of the stages up to `dict`, named explicitly (`MINI_STAGES`), because C5's checks target the starter set, not the mini dataset.
- **C5's checks are issues only in a complete build** (the default of `validate` without `--dir`); on a partial set (`validate --dir packages/testkit/mini`) the content targets are warnings. Trigger rules are always issues. A mock review is a warning, so validate passes with mock fills.
- **Target triggers are taken from the 22 mini triggers**, because C4's list does not exist yet; every one is a trigger C4 will hold under the same id.
- **Proper names are left out of the 90 % share**; a learner does not need *Bratislava* or *Peter* in the top 2,000. Their counts are in the report.
- **No comparatives or superlatives in the texts**: C1 drops them from the morphology, so *lepší*, *najdôležitejší*, *starší* are not known forms. The texts say it another way. *lepšie* is known as an adverb lemma.
- `scenarios.slovak` (known forms in title, setting, opening line and hints) is an addition.

## Known gaps and follow ups
- **`validate` on the full build fails in `links` until C4's `triggers.jsonl` is part of the set**: the 50 target triggers of the scenarios (21 distinct ids) point at trigger ids, and the core links check looks them up in the set's `triggers.jsonl`. With C4 merged (and holding the mini ids) this resolves; `scenarios.rules` then also checks each trigger's case against the set.
- **No review has run.** All 12 texts are `unreviewed` until `library --fill live` (about $0.31). A person should read any `revise` verdict and fix the text by hand; the stage never rewrites a text.
- The texts were written and checked against the morphology and ranks, not by a native speaker.
- `library`'s fingerprint covers its own folder and `lib/`; the scenarios stage imports `library/setvocab.ts` and `vocab.ts`, so after changing those run `scenarios --force`.
- After editing an authored text or scenario, rerun `fixtures/make-fixture.py` (needs `content/build/morph` and `freq`), or the tests report the new words as unknown.
