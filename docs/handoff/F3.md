# F3 Database and test kit
Status: done with gaps

## What was built
`@app/db` (`packages/db`) and the `src/` part of `@app/testkit`.

| Piece | Where |
|---|---|
| Drizzle schema, 27 tables (13 `ling`, 14 `app`), check constraints from the contract enums (`oneOf`, `allOf` in `src/schema/helpers.ts`), owner policies on every `app` table | `src/schema/{ling,app,helpers,index}.ts` |
| Migrations | `drizzle/0000_roles.sql` (custom), `0001_schema.sql` (generated), `0002_security.sql` (custom), `drizzle/meta/` |
| `createDb`, `withUser`, `withSystem`, `queryRows`, types `Db`, `Tx`, `Database` | `src/client.ts` |
| `migrate`, `installAuthStub`, `MIGRATIONS_FOLDER`, `AUTH_STUB_SQL` | `src/migrate.ts`, `src/auth-stub.ts` |
| `loadContent`, `validateContent`, `currentContentVersion`, `ContentValidationError` | `src/content/load.ts` |
| CLI: `pnpm db:migrate`, `pnpm --filter @app/db db:load <folder>`, `pnpm db:generate` | `scripts/db.ts`, `drizzle.config.ts` |
| Test kit: `createTestDb`, `createFactories`, `FACTORY_FOR_TABLE`, `MINI_CONTENT_DIR`, `uuidv7`, `MESTO_WORD_CONTENT`, `V_MESTE_PHRASE_CONTENT` | `packages/testkit/src/` |

Roles: migration 0000 creates `authenticated` (NOLOGIN NOINHERIT) when missing and `app_api` (LOGIN NOINHERIT NOBYPASSRLS, no password), and grants `authenticated` to `app_api`. Migration 0002 grants `authenticated` select on `ling` and select/insert/update/delete on `app` (no update on `review`, `attempt`, `ai_call`), `app_api` select on `ling` plus insert/update on `ling.sense`, nothing on `app`; and forces row level security on all 14 `app` tables. Policies: `<table>_{select,insert,update,delete}_own`, to `authenticated`, `"user_id" = (select auth.uid())` in `using` and `with check`.

## How to run and test it
`pnpm test --filter db` and `pnpm test --filter testkit` (about 10 s), or `pnpm check`.
- `packages/db/src/schema.test.ts`: 27 tables on a fresh PGlite; no drift: `drizzle-kit pull` of the migrated database compared with the schema snapshot (tables, columns, types, defaults, keys, foreign keys, uniques, check, index and policy names), and `generateMigration(last snapshot, schema)` is empty.
- `packages/testkit/src/security.test.ts`: reads the `app` tables from the catalog and fails if one lacks `user_id`, forced RLS or a policy, or has no factory; policy text and commands per table; for every table user A cannot see, update, delete or insert B's rows, cannot hand its rows to B, and can still work on its own.
- `packages/db/src/client.test.ts`: `app_api` owns nothing, cannot bypass RLS, inherits nothing, can switch to `authenticated`; without the switch it gets "permission denied" on every `app` table; `withUser`/`withSystem` behaviour; check constraints.
- `packages/db/src/content/load.test.ts`: an inline content set loads into all 13 `ling` tables; a second load leaves every row's `xmin` unchanged and writes no version row; a new build updates, keeps lemmas missing from the files and run time glosses, drops stale lesson steps; invalid sets fail with `file:line` and write nothing.

## Differences from the specification, and why
- F2 was not on `main` when this started, so the branch contains F2's commit (fast forward) and a merge of `origin/main` (F2, F7).
- `auth.uid()` is not created by the migrations. `AUTH_STUB_SQL` (role `authenticated` if missing, schema `auth`, `auth.uid()` reading `request.jwt.claims` like Supabase, only if missing) runs before them; `migrate()` installs it automatically in pglite mode, `migrate(db, { authStub: true })` elsewhere. Migration 0000 fails with a clear message when `auth.uid()` is missing.
- The table `app.text` is exported as `appText`, so it does not shadow Drizzle's `text` column builder.
- Index and constraint names are fixed by us (e.g. `note_user_word_idx`, `card_note_template_unique`); the contract SQL left them unnamed.
- "drizzle-kit reports no drift": `drizzle-kit/api`'s `pushSchema` cannot introspect PGlite (it drops query parameters), and `drizzle-kit pull` rewrites check, index and policy expressions. So the drift test compares structure and names via `pull`, and the expressions are checked against `pg_policies` in the security test.
- Timestamps are `Date` in TypeScript (Drizzle's default mode); `ai_call.cost_usd` is a string (numeric).
- `withSystem` runs `set local role app_api` in every mode, so local mode (PGlite, superuser) behaves like production.

## Known gaps and follow ups
- The postgres.js path and both migrations were not run against a real Postgres or Supabase (none reachable here); only PGlite (Postgres 18). On Supabase check that the migration role may `grant authenticated to app_api`.
- `app_api` has no password. Per project, once: `alter role app_api password '…'` (never in the repository), then use it in `DATABASE_URL` (on the Supavisor pooler the user name is `app_api.<project-ref>`).
- `loadContent` needs to run as the owner of the tables (migration role / PGlite superuser), not as `app_api`.
- The mini dataset is not here yet (F9). `MINI_CONTENT_DIR` is `packages/testkit/mini/`, and the loader expects the content files and `manifest.json` directly in it; if F9 uses a subfolder, change that one constant. The test that loads `mini` is skipped until `mini/manifest.json` exists.

## Notes for packages that depend on this one
- **Get a db:** `const database = createDb({ mode: 'pglite', dataDir: '.local/pgdata' })` or `createDb({ mode: 'postgres', url: process.env.DATABASE_URL })` (pool of 5, `prepare: false`). Then `await migrate(database)` in local mode and `await loadContent(database, MINI_CONTENT_DIR)`. `currentContentVersion(database.db)` gives the health endpoint its content version. `database.close()` at shutdown.
- **Transactions:** `database.withUser(userId, async (tx) => …)` sets `role authenticated` and `request.jwt.claims = { sub, role }` for that transaction only; RLS applies and `ling` is read only. `database.withSystem(async (tx) => …)` runs as `app_api`: read `ling`, insert/update `ling.sense`, nothing on `app`. Free functions `withUser(db, …)`/`withSystem(db, …)` take a bare `Db`. `withUser` throws on a non-uuid id. Services take `tx: Tx`. No network call inside either.
- **Tables:** `import { note, card, review, appText, ling… } from '@app/db'` (all tables are top-level exports; `schema` is the namespace). The schema is passed to Drizzle, but no `relations()` are defined; prefer the query builder. Raw SQL: `queryRows<T>(tx, sql\`…\`)` returns rows on both drivers (PGlite returns `{ rows }`, postgres.js an array). Column names in JSON are camelCase on the Drizzle objects; grammar columns are `gCase`, `gNumber`, `gGender`.
- **Test kit:** `const t = await createTestDb({ content: 'mini' })` in `beforeAll` (about 2 s; one per file), `await t.close()` in `afterAll`, `await t.resetApp()` to wipe learner rows between tests. `t` is a `Database` plus `factory` and `content` (the `LoadResult`). Options: `content` is `'mini'`, any content folder, or omitted (empty `ling`).
- **Factories:** `t.factory.profile|userLemma|note|card|review|attempt|lessonProgress|text|conversation|message|tutorError|placement|aiCall|contentReport(overrides?)` insert one valid row as the owner (RLS bypassed) and return it. Missing parents are created: `review()` makes a card, a note and a profile; pass `userId` (and `noteId`, `cardId`, `conversationId`, `messageId`) to attach. `note()` defaults to a phrase note (word notes are unique per learner and lemma); pass `content: MESTO_WORD_CONTENT` for a word note of lemma 20. Ids are UUID v7 (`uuidv7()`).
- **A new `app` table** needs `user_id` with `owner()`, `...ownerPolicies('<name>')`, a grant and `FORCE ROW LEVEL SECURITY` in a new custom migration, and a factory in `FACTORY_FOR_TABLE`; the security test fails otherwise. Change the schema, then `pnpm db:generate` (and `drizzle-kit generate --custom` for grants).
