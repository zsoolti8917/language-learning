**`@app/srs`** (`packages/srs/src`, imports only `@app/contracts`, `@app/ling`, `ts-fsrs`)

```ts
newState(now: Date): SchedulerState
schedule(state: SchedulerState, rating: Rating, now: Date, opts: { desiredRetention: number }):
  { state: SchedulerState; snapshot: SchedulerSnapshot }
replay(reviews: readonly { rating: Rating; answeredAt: Date }[], opts: { desiredRetention: number; createdAt?: Date }):
  { state: SchedulerState; snapshot: SchedulerSnapshot }

  { grade: Grade; rating: Rating; diagnosis: Diagnosis }

parseSchedulerState(value: unknown): SchedulerState   // TypeError on other JSON or another version
isSchedulerState(value: unknown): value is SchedulerState
snapshotOf(state: SchedulerState): SchedulerSnapshot
ratingForGrade(grade: Grade): Rating                  // RATING_FOR_GRADE: correct 3, close 2, wrong 1, revealed 1
isKnownStability(stability: number | null | undefined): boolean   // > KNOWN_STABILITY_DAYS (21)
// SchedulerSnapshot = Omit<CardSnapshot, 'cardId'>
// Constants: SCHEDULER_VERSION ('fsrs7.1'), LEARNING_STEPS ['1m','10m'], RELEARNING_STEPS ['10m'],
//            DEFAULT_DESIRED_RETENTION 0.9, MAXIMUM_INTERVAL_DAYS 36500
```

`SchedulerState` is plain JSON: `{ v: 'fsrs7.1', state: 0..3, dueAt, lastReviewAt, stability, stabilityFast, difficulty, reps, lapses, learningStep, scheduledDays }` with ISO 8601 UTC times. Store it as is in `app.card.scheduler`.

## How to run and test it
`pnpm test --filter ling`, `pnpm test --filter srs`, `pnpm check`.

- `diagnose.test.ts`: all five results, with *do meste* (other_case s6, `case_after_preposition`), *zenam* for *ženám* (diacritics), *z ulicy* (wrong_pattern, pattern žena), the pair *mesta* / *mestá* both ways, *ženov* for *žien* (`genitive_plural`).
- `text.test.ts`: 21 sentence cases (abbreviations, ordinals, dates written with spaces, Roman ordinals, quotes, line breaks), and fast-check properties on tricky strings (decomposed accents, emoji, NBSP, BOM, zero width joiner, lone surrogates): every token slice re-tokenizes to exactly that token, only white space falls between tokens, sentence spans are trimmed and ordered and hold every non-space character, and no token is cut by a sentence.
- `scheduler.test.ts`: fixed clock; new card → 1 min → 10 min → review (≥ 1 day); a lapse → relearning 10 min → review; higher retention gives a shorter interval; JSON round trip; property test that `replay` equals step by step `schedule` for random logs given in any order.
- `grade.test.ts`: *mesta* for *mestá* wrong (other_case), *zenam* for *ženám* close / wrong with strict accents.
- `package.test.ts` in both: imports limited as the rules say, no host globals (`process`, `window`, `fetch`, `console`, `crypto`, timers…), dependency list.
- Every form in the test tables (*mesto*, *žena*, *ulica*, *pekný*, `packages/ling/src/fixtures/tables.ts`) was checked against the SNK file `ma-2015-02-05` (all 98 form/tag pairs match exactly).

## Differences from the specification, and why
- **Dependency on F2**: this branch started from F1 (`6276e35`), which had an empty `contracts`. F2's commit `e40993f` (branch `wp/f2-contracts`, already merged into the project branch) was fast-forwarded into this branch first. No F2 file was changed.
- **`schedule` and `replay` return `SchedulerSnapshot` = `CardSnapshot` without `cardId`**: the specified signatures take no card id, so the caller adds it: `{ cardId, ...snapshot }`.
- **`replay` takes an optional `opts.createdAt`** (the card's creation time). Without it, the card starts new at its first review; the result is the same. An empty log without `createdAt` throws.
- **ts-fsrs 6**: `DefaultScheduler()` is asynchronous, so the package builds the same preset synchronously with `defineScheduler` + `FSRS7Model` + the default middlewares. FSRS-7 with its default weights, fuzz off, maximum interval 36 500 days. **`allowModelOverride` is off**: with the FSRS-7 default (on), a new card answered good skips the steps and is due in about 4.8 days, which breaks "a new card repeats after 1 and 10 minutes".
- An answer stamped before the card's last review is scheduled at the last review's time (ts-fsrs throws on negative elapsed time). The server still replays the log for out of order answers.
- A new card's snapshot has `dueAt`, `stability` and `difficulty` null.
- `diagnoseForm` takes `(typed, input)` with `input` shaped like `ExerciseItem`/`ReviewItem` and returns an object with the diagnosis plus its detail (tags and readings for `other_case`, the pattern for `wrong_pattern`). The stem for `wrong_pattern` comes from, in order: `input.stem`; the accepted answer minus the own pattern's ending when `input.pattern` is a key of `siblingEndings`; otherwise every cut of the accepted answer by up to 4 letters. Comparison is after folding accents.
- `errorTypeFor`: trigger kinds other than preposition, verb and numeral (e.g. quantifier, question) give `case_other`, as the docs name only those three.
- Form map keys are lower case NFC (`formKey`); rows differing in capitals are merged.
- `gradeAnswer` never returns `revealed`; the client sets it. Capital letters never matter, as `normalizeAnswer` lower cases.
- Sentence splitting rules beyond the docs: an empty line always ends a sentence; a single line break ends one when the next line starts with a capital letter, opening quote or dash and the line does not end with `,;:(-–„`.

## Known gaps and follow ups
- The `wrong_pattern` guess without a known stem can, in rare cases, name a pattern for a typo; B5 can pass `pattern` (own ending in `siblingEndings`) or `stem` (`stemOf`) to make it exact.
- Abbreviation lists are hand written; the pipeline (C3) may extend them from data.
- Contracts: `FormTagSchema` accepts `v:` with nothing after it while `FormTagsSchema` does not; `ling` accepts both like `FormTagSchema`.

## Notes for packages that depend on this one
- Client and server: `gradeAnswer(item.typed, item.answers, item.formMap, { strictDiacritics })` then `schedule(parseSchedulerState(item.scheduler), rating, now, { desiredRetention })`. Store `result.state`; send `{ cardId, ...result.snapshot }`.
- Server sync: `replay(log.map(r => ({ rating: r.rating, answeredAt: new Date(r.answeredAt) })), { desiredRetention, createdAt })`.
- Coverage: a word is known when `isKnownStability(card.stability)`.
- B5 trainer: `diagnoseForm(typed, exerciseItem)` works on an `ExerciseItem` as is; pass `{ ...item, pattern: item.features.pattern, gender: item.features.gender }` for exact stems and gendered readings. Then `errorTypeFor(d, { triggerKind: item.trigger?.kind, expectedTag })`, and `bucketOf(item.features)` / `bucketKey` for mastery.
- C1 and B2: `buildFormMap(rows)` from `ling.form` rows; `readTags` decodes tags for payloads.
- B3 and the pipeline: `splitSentences` and `tokenize` give offsets into the text as given (UTF-16 units), ready for `TextAnalysis` (`s`, `e`, `t`).
- Changing the stored state layout means a new `SCHEDULER_VERSION`; `parseSchedulerState` refuses other versions.
