## How to run and test it
`pnpm test --filter contracts`; `pnpm openapi` rewrites `docs/openapi.json`; `pnpm check`. Tests prove: every example parses with its schemas and the success status (`endpoints.test.ts`), 45 endpoints and none without an example, examples use only the 72 mini lemma ids with matching lemmas and blanks that hold the answer (`fixtures/fixtures.test.ts`), `foldAscii` on all 17 accented letters (`text.test.ts`), only zod is imported (`package.test.ts`), and the OpenAPI document is structurally valid 3.1 (refs resolve, path params match templates, unique operation ids) and equals the committed file (`openapi.test.ts`).

## Differences from the specification, and why
- The endpoint tables list 45 endpoints, as the plan says; no difference.
- The `Number` enum is exported as `NUMBERS`, `GrammaticalNumberSchema` and type `GrammaticalNumber`, so it never shadows the global `Number`.
- `scripts/openapi.ts` writes to stdout and the package script redirects it to the file: the dependency check forbids `node:fs` anywhere in `@app/contracts`, scripts included. `tsconfig.json` of the package now also includes `scripts/`.
- Placement case items write the gap as `___` in `sentenceSk`, so items carry no answers.
- Shapes the docs leave open were fixed here: `NoteSummary`, `NoteDetail` (`{ note, card, reviews }`), `Today`, `StatsSummary`, `Export`, `TextDetail` (TextSummary + body, analysis, error, lemmaStatus, phrases), `LessonDetail`, `PatternDetail`, `ConversationDetail` (`{ conversation, scenario, messages, errors }`), `TutorSummary`, `LessonScore` (`{ correct, total }`), the `POST /notes` body (word: `lemmaId` + optional capture `context`; phrase and case sentence: full `content`), stream `resolved` items and `done.cardsCreated` (note ids). Batch bodies take at most 200 items.
- Success status is 200 for every create except `POST /texts` (202) and `POST /reports` (201), as the tables say.
- An external OpenAPI linter could not be run here; validity is proven by the structural test.

## Known gaps and follow ups
- `TutorAnalysis` (route `tutor.analyze`) is owned by B9 and is not here.
- Port types (`WordNoteInput` etc.) are F5's; `Lemma`, `Sense`, `Paradigm`, `FormCandidate` exist here for them to reuse.

## Notes for packages that depend on this one
- Query and path schemas coerce strings (`limit`, `band`, lemma `id`, sentence `n`; `archived` is `z.stringbool()`), so validate raw query objects directly. Request bodies strip unknown keys.
- Handlers type their input with `RequestOutput<'name'>`, clients with `RequestInput<'name'>` and `ResponseOf<'name'>`. Build URLs with `API_BASE + buildPath(e.path, params)`.
- Mocks: `examples[name].ok[0]` is the default reply; error examples carry `ErrorResponse` with the status from `ERROR_STATUS`. The stream is `formatSseEvent` per event of `stream`.
- `TutorErrorSchema` and the stream's error refuse a `prompted` error that carries `expected`.
- Content rows omit null fields; defaults (`topForms`, `flags`, `verified`, `course`, …) are filled by parsing. The loader computes `lemma_ascii` and `form_ascii` with `foldAscii`. Lesson rows embed their steps, sentence rows their `links`.
- After changing a schema, run `pnpm openapi`; a test fails while `docs/openapi.json` is stale.
- F9: example ids and words come from `src/fixtures/mini-lemmas.ts`; trigger ids used are `prep-do`, `prep-v-loc`, `prep-pre`, `prep-s-ins`, `verb-pomahat`; patterns `mesto`, `zena`, `chlap`; exercise ids `ex-3fa94c21d0`, `ex-5c2e81b7a4`, `ex-9d04b3e2f1`, `ex-7b21c0d4e9`, `ex-b4e1f09a37`; sentence `tat-482913`. Aligning the dataset with them is welcome but not required.
