# I1 End to end integration
Status: done

## What was built
- **`pnpm e2e`** (e2e/scripts/run.mjs, e2e/playwright.config.ts): picks two free ports (the
  approach of `e2e:all`), starts the API in local mode (`APP_ENV=local DB_MODE=pglite` in memory,
  `AUTH_MODE=dev`, `AI_MODE=mock`, `VALIDATE_RESPONSES=true`) and a production build of the client
  served by `vite preview` with `VITE_MOCK_API=false`, proxying `/api` to that API. Chromium at
  390x844 (mobile, touch), `trace: 'off'`, generous timeouts, two workers (`E2E_WORKERS`).
- **Startup port check** (apps/api/src/platform/stand-in.ts): every stand-in under
  apps/api/src/testing is marked with `markStandIn`; `createRuntime` calls `assertRealPorts`, which
  refuses to start when morphology, dictionary, notes, attempts or analyzer is a stand-in, or when
  the gateway is the mock outside `AI_MODE=mock`. The server logs
  `Ports: morphology=real, dictionary=real, notes=real, attempts=real, analyzer=real, gateway=mock`.
  Tests: stand-in.test.ts (local runtime is all real, every stand-in is refused, the mock gateway is
  refused with `AI_MODE=anthropic`).
- **Response validation during the flows** (e2e/src/contract.ts, fixtures.ts): every `/api/`
  response the page receives is checked against its contract (status, body schema, error shape,
  tutor stream events); the test-side `api` client validates too, and the API runs with
  `VALIDATE_RESPONSES=true`. A flow fails on contract drift, any 5xx or any console error.
- **Flows** (e2e/flows):
  - first-run: onboarding, placement to its result, Today.
  - review: answers graded on the phone, two answered offline, one outbox batch on reconnect,
    server grades and reps; deck search, report from a card, suspend/resume, edit, delete.
  - reader: import, case sheet with trigger, translation, Known, save a word, the capture as a
    review card; a starter text from the library with a saved phrase.
  - lesson: checkpoint failed then passed, completion, cards in review.
  - trainer: a session moves mastery off `unseen`; at most five new cards a day.
  - words: sorting 25 words with a swipe and an undo, batches sent, server counts.
  - tutor: one error fixed by the learner (self corrected), one corrected, card, hint, summary,
    the card in review; a disputed correction reported and its card paused.
  - account: export parsed with the export schema, deletion, every table empty.
  - screens: all 18 routes load for a learner with history, no error state, no sideways scroll.
  - contract: self-check of the validator.
- **`pnpm seed:demo`** (apps/api/src/testing/demo-seed.ts): resets and creates the dev login
  learner (`0193a1b2-c3d4-7e5f-8a6b-000000000001`) with 21 days of history made through the real
  API on a fixed clock: placement, word sorting, three lessons, trainer sessions, two texts with
  captures, two tutor conversations, daily reviews with skipped days. Deterministic (seeded).
  Local PGlite only; it refuses production. `DEMO_DAYS` and `DEMO_USER` override.
- **CI**: the `browser` job in .github/workflows/ci.yml runs `pnpm e2e -- --repeat-each=3` and
  uploads e2e/test-results on failure.

## How to run and test it
- `pnpm e2e` (all flows), `pnpm e2e -- --repeat-each=3`, `pnpm e2e -- flows/tutor -g disputed`.
- `E2E_SKIP_BUILD=1 E2E_DIST_DIR=<dir>` reuses an earlier client build; `E2E_KEEP=1` keeps it.
- `pnpm seed:demo` writes to `PGLITE_DIR` (default local data folder); then `pnpm dev` and log in
  as the dev user. Test: apps/api/src/testing/demo-seed.test.ts.
- Never call the real Claude API: the flows run with `AI_MODE=mock` and the scripted prompts in
  packages/ai/prompts (tutor answers, "[EN] …" translations).

## Differences from the specification, and why
- The seed script lives in apps/api/src/testing, not in e2e: @app/e2e may import only contracts and
  testkit, and the seed needs the API app. The root script `seed:demo` still goes through e2e.
- Response validation is done test-side: the production client build does no response
  validation, and the spec asks for the real client without the mock server.
- The words flow sorts 25 words, not a whole band; a band is 1000 words.

## Known gaps and follow ups
- The contract example for `words.bands` still shows 500-wide bands (packages/contracts, owned by
  the contract package); the API and the client agree on 1000.
- A repeated `POST /texts` with the same id answers 200, not 202; the validator accepts 200 as a
  repeat for 201/202 endpoints. Repeated foreign ids answer 409 (B4, B9).
- B6 unit tests still use a notes double; the real notes port is covered by the words and placement
  flows and the seed. B5's daily card cap is proven with the real notes port in the trainer flow.
- Flaky test outside I1 (not edited): apps/api/src/modules/placement/placement.test.ts, "the same
  answers return the same next round", changes an answer with `choice: 4 - choice`, which is the
  same answer when the choice is 2, so it fails now and then with "expected 200 to be 409". The
  owner should pick a different choice (for example `choice === 0 ? 1 : 0`).
- Answers made while a review batch is in flight merge into the next batch, so the review flow
  counts answers sent, not batches. Wrong trainer answers on meaning choices make no card.
- No new dependencies.

## Notes for packages that depend on this one
- I4/I5: add a flow per new feature in e2e/flows using the `api`, `watch` and `page` fixtures;
  `onboard(api)` gives a fresh learner per test. The `watch` fixture fails a test on any console
  error, 5xx or contract drift; `watch.allow(pattern)` allows an expected console error.
- A new port stand-in must be wrapped in `markStandIn`, or the startup check cannot catch it.
- The seed is the quickest way to see screens with history; extend `seedDemo` when a feature adds
  history (keep it deterministic: the rerun test compares summaries).
