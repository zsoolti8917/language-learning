# F7 Design system
Status: done

## What was built
- `apps/web/src/ui/tokens.css`: colour, spacing, radius and type tokens as CSS variables (`--ui-*`) for a light and a dark theme, mapped into Tailwind 4 with `@theme inline`, safe area utilities (`pt-safe`, `pb-safe`, `pl-safe`, `pr-safe`, `px-safe`), the focus ring and the reduced motion rule. One colour per case (`--ui-case-nom` … `--ui-case-ins`, each with a `-soft` tint).
- The 13 components in `apps/web/src/ui/`, exported from `apps/web/src/ui/index.ts`: Button, Input, AccentBar, AnswerInput, Sheet (vaul), Card, Tabs (Radix), Toast with ToastProvider and useToast (Radix), ProgressRing, CaseBadge, TokenText, EmptyState, Skeleton. Helpers: `cn`, `CASES`, `CASE_CLASSES`, `caseColorVar`, `insertAtCaret`, `fieldClasses`, `buttonClasses`, `UI_STRINGS`.
- `apps/web/src/ui/README.md`: every component with its props, every token with its Tailwind utility, the rules, how to import.
- Gallery: `apps/web/gallery.html` (a second HTML root of the web app) → `apps/web/src/ui/gallery/` (`main.tsx`, `Gallery.tsx`, `gallery.css`). Every component in every state, in a light and a dark block, plus a page theme switch (`?theme=light|dark`). No router, no data layer.
- Tests beside the code: `AccentBar.test.tsx`, `AnswerInput.test.tsx`, `TokenText.test.tsx`, `overlays.test.tsx` (Sheet, Tabs, Toast), `components.test.tsx` (the rest), `contrast.test.ts` (WCAG AA computed from `tokens.css`), `imports.test.ts` (no import from `features/`, `lib/` or `@app/*`). Shared setup in `ui/test/setup.ts`.
- Playwright for the gallery: `apps/web/e2e-ui/playwright.config.ts` and `apps/web/e2e-ui/gallery.e2e.ts`, script `test:ui` in `apps/web/package.json`.

## How to run and test it
- `pnpm check` (unit, contrast and import tests run in the `@app/web` Vitest project; `pnpm test --filter web` for only these).
- `pnpm --filter @app/web test:ui`: Playwright at 390 x 844, projects `light` and `dark`, starts Vite on port 5179 itself. Result on 2026-11-17: 16 passed (8 tests x 2 themes): no console error or warning, no sideways scroll, every section present, tap targets ≥ 44 px, input text ≥ 16 px, the accent bar inserts at the caret and keeps the focus, answer states, sheet at the bottom edge with Escape and focus return, toasts, visible focus ring, arrow keys in tabs and TokenText, reduced motion stops the skeleton pulse.
- Look at it: `pnpm --filter @app/web dev`, open `http://localhost:5173/gallery.html`.

## Differences from the specification, and why
- Tokens live in `apps/web/src/ui/tokens.css`, not `apps/web/src/styles/`, as the brief asked. `styles/` stays empty.
- `apps/web/src/ui/biome.json` (nested config, extends the root) turns on Biome's `tailwindDirectives` CSS parser option for `ui/` only; without it Biome cannot parse `@theme` and `@utility`. The root `biome.json` is unchanged.
- `vite.config.ts` is unchanged: Vite serves `gallery.html` in dev as is. `vite build` builds only `index.html`; the gallery is a development page.
- Components show no hard-coded messages-file text: each text has an English default in `ui/strings.ts` and a prop to override it, because `ui` must not import `lib` (where the messages file will live).
- AccentBar has an optional shift key (`allowUppercase`) for free text such as the tutor chat. Answers do not need it.

## Known gaps and follow ups
- `apps/web/src/index.css` (F1/F6) still imports Tailwind only. F6 adds `@import "./ui/tokens.css";` after `@import "tailwindcss";` and wraps the app in `<ToastProvider>`.
- The Playwright files under `apps/web/e2e-ui/` are not in `apps/web/tsconfig.json` (`include` is `src`, `vite.config.ts`), so `tsc -b` does not check them. They pass a manual `tsc --strict` check. F6 can add `e2e-ui` to `include` when it adds its own Playwright project.
- The web Vitest config has no `setupFiles`, so each ui test imports `./test/setup`. If F6 adds a global setup (jest-dom, cleanup), the imports become harmless duplicates.
- On the cloud containers the Playwright config uses `/opt/pw-browsers/chromium` (its revision differs from the one Playwright 1.65.1 expects). `PW_CHROMIUM_PATH` overrides it; elsewhere Playwright's own browser is used.
- The docked accent bar follows the visual viewport. It was not tried on a real iPhone.

## Notes for packages that depend on this one
- Import from `ui` only: `import { Button, AnswerInput, Sheet, TokenText, CaseBadge, useToast } from '../../ui';`. Never edit `ui/`; ask for a change.
- Use token utilities (`bg-surface`, `text-fg`, `text-fg-muted`, `border-border`, `text-case-gen`, `rounded-card`, `min-h-tap`, `px-gutter`, `pb-safe`), never raw colours and never `dark:`. The theme switches by variables: set `document.documentElement.dataset.theme = 'light' | 'dark'`, or leave it unset to follow the system.
- Show a case colour only through `CaseBadge` or next to the case name. `CASES` has the same values as `Case` in contracts.
- Every typed Slovak answer goes through `AnswerInput` (it sets `lang="sk"`, autocorrect, autocapitalize and spellcheck off, and carries the accent bar). Map grading onto `state`: `correct` → correct, `close` → close, `wrong` → wrong.
- `TokenText` takes `{ start, end, status }` tokens: map `TextAnalysis` tokens with `start: t.s - sentence.s` (offsets into the text you pass), `status` from `lemmaStatus` of `t.l`, and no status for punctuation. Status values equal `LemmaStatus`.
- Pass interface text from the messages file through props (`label`, `stateLabels`, `statusLabels`, CaseBadge `label`, Sheet `title`, ToastProvider `label` and `closeLabel`).
