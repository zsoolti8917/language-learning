# B5 Declension module
Status: done

## What was built
The six declension endpoints and the real `AttemptsPort`, all in `apps/api/src/modules/declension/`.

| File | Holds |
|---|---|
| `routes.ts` | The six handlers; each runs one `withUser` transaction. The session id and a missing seed are made before the transaction. |
| `service.ts` | Course, lesson detail, progress (completion, cards, next lesson), session builder wiring, attempts (second diagnosis, rows, daily cap), pattern, `getMastery`. |
| `repo.ts` | All SQL: `ling.lesson`, `lesson_step`, `exercise`, `form`, `lemma`, `pattern`, `trigger`; writes `app.attempt`, `app.lesson_progress`; reads `app.profile` (learner day) and `app.note` (daily cap). |
| `items.ts` | Pure: exercise row → `ExerciseItem` (form map, phrase form map, sibling endings, trigger label), `diagnoseAnswer` (server diagnosis). |
| `mastery.ts` | Pure: the mastery formula, levels, all 56 buckets. |
| `select.ts` | Pure: the seeded session builder (mulberry32). |
| `port.ts` | `createAttemptsPort(ctx)`: `record` (repeat-safe insert, future time set to now) and `getMastery`. |

Behaviour:
- **Course**: a stored `lesson_progress` row wins; otherwise the first lesson is `available` and each next one opens when the one before is `completed` or `tested_out`. `mastery` lists all 56 buckets (unseen ones with 0 attempts).
- **Lesson detail**: steps in order with their exercises as `ExerciseItem`; triggers are the lesson's `focus.triggerIds` plus the triggers step's ids; `progress` or null.
- **Progress**: a score at the checkpoint's `passShare` (default 0.75) completes the lesson, with or without `status`. `status: 'completed'` without such a score, `locked` and `available` give 409. A completed lesson stays completed (later saves only move `stepIndex`) and keeps its best score. On the first completion it creates up to 10 case sentence notes through `NotesPort.createCaseSentenceNote` (source `declension`, `sourceRef { kind: 'lesson', lessonId }`): exercises with the most wrong attempts first, then step order; meaning choices are left out. Completing or testing out inserts an `available` row for the next lesson if it has none. Any lesson can be started early (`in_progress`).
- **Sessions**: `lesson` (given id, else the first in progress, else the first available), `mixed` and `weak` (every lesson not locked). Weight of a bucket = share × (1 − mastery); share = the highest focus weight of the chosen lessons, 0.05 for a bucket no lesson names. At least `ceil(30% × size)` items come from `strong` buckets when there are any (drawn by share). In `weak` mode the rest comes from the 3 weakest non-strong buckets. Within a bucket: never answered first, then answered longest ago. Seeded: same seed + same history → same items (session id differs).
- **Attempts**: unknown exercise ids → 400 naming `body.attempts.<i>.exerciseId`. Each answer is diagnosed again with `diagnoseForm`/`errorTypeFor` (the client's `correct` and `clientDiagnosis` are ignored); the row gets lemma (the noun of a phrase), case, number, gender, pattern, trigger, diagnosis, error type, given, expected, given case, session id as `source_ref`. Ids already stored are skipped and still counted in `accepted`. New wrong **trainer** items become case sentence notes (`sourceRef { kind: 'trainer', exerciseId }`), at most 5 per learner day. `mastery` lists the buckets of the batch.
- **Mastery**: newest 30 attempts per bucket, `w = 0.9^i`, x = 1 / 0.5 (correct retry) / 0; `attempts` is the bucket's total count; below 5 attempts `unseen`, < 0.6 `weak`, ≥ 0.85 `strong`. Rows without gender are not bucketed.

## How to run and test it
`pnpm test --filter api` (or `pnpm exec vitest run src/modules/declension` in `apps/api`, about 6 s), `pnpm check`.
- `mastery.test.ts`: hand computed values, retries (0.5 and wrong retry 0), the 30 window, the unseen rule (< 5 attempts, even at 1.0), levels at the borders.
- `select.test.ts`: same seed/any input order → same session; other seed differs; `weak`: ≥ 30% strong and most items from the weakest buckets over 20 seeds, at most 3 weak buckets; `mixed` weights; no strong share without strong buckets; not-seen-lately preference; fill when buckets run out.
- `items.test.ts`: every mini exercise gives a contract-valid item graded `correct` by its answer; sibling endings (masculine family); phrase form map (*novú prácu*); meaning choices; **the three examples**: *do meste* → `other_case` / `case_after_preposition` (given case loc), *zenam* for *ženám* → `diacritics` / `spelling`, *z ulicy* → `wrong_pattern` / `pattern_ending`; plus `genitive_plural` and `not_a_form`.
- `declension.test.ts` (one PGlite with the mini set): every endpoint with its schema; early start; completing at 75% creates 10 cards once with wrong items first, a repeat and later saves create none, the next lesson opens; 409/400/404 cases; sessions repeat by seed, `lesson` mode, `weak` mode on a real history; attempts stored with server diagnosis, repeat-safe, the zenam / z ulicy rows through the endpoint (two test-only exercises inserted), daily cap 5 and reset next learner day, future time clamped; port mastery against a hand computed 35-attempt history; isolation.
- `port.test.ts`: the real port passes `runAttemptsSuite`.

## Differences from the specification, and why
- **Isolation test**: no declension endpoint addresses a learner row by id (paths name lessons and patterns), so "B gets `not_found` for A's rows" is shown as: B sees none of A's progress, attempts or mastery, a lesson path with A's attempt id is 404, and B sending A's attempt id is skipped as a repeat without touching A's row.
- **Unseen buckets in selection**: the docs fix the level but not the weight; an unseen bucket weighs as mastery 0.5 (`UNSEEN_MASTERY`), so it is neither the weakest nor strong.
- **Strong share** uses level `strong`; with no strong bucket the 30% goes to the rest.
- **Sibling endings** include the target's own pattern (F4 recommends it: `diagnoseForm` then cuts the exact stem) and every noun pattern of the gender family; masculine animate and inanimate are one family (as in the F2 example). Phrase targets (two lemmas) carry no sibling endings; their `formMap` keys are whole phrases (`"novú prácu": ["s4"]`), falling back to the noun's map if a word lacks an agreeing form.
- **Meaning choices** (`choice_meaning`): right when `typed` is the right option's text; a wrong one is stored with `diagnosis` null and error type `case_other`. They never become cards.
- **Daily cap** counts `app.note` rows of the day with source `declension` and `source_ref.kind = 'trainer'`; only trainer attempts are promoted (architecture: "Wrong trainer items become review cards"); lesson items go in at completion.
- **Forms are read in repo.ts** from `ling.form` with the open transaction, not through `MorphologyPort` (one query for all lemmas of a batch; no second connection).
- **Lesson unlocking** follows course order; `prerequisites` (empty in the mini set) is not used.

## Known gaps and follow ups
- With the notes **recorder** stand in (until B1 merges) notes are not in `app.note`, so the daily cap cannot bite; the tests use a small `NotesPort` that writes `app.note`. B1's real port must store `source`, `source_ref` and `created_at` (preferably from `deps.clock`) for the cap to work, and keep one note per exercise.
- Not run on real Postgres.
- `profile.current_lesson_id` is not touched (the profile module owns it).

## Notes for packages that depend on this one
- `AttemptsPort.record(tx, attempts)`: pass `gender` or the row is never in a bucket. Ids already stored are skipped; future times become now. `getMastery(tx)` lists only buckets with attempts; use 56-bucket `allBuckets` semantics yourself if needed (or read `GET /declension/course`).
- M4: sessions and lesson items carry `siblingEndings` including the own pattern, so `diagnoseForm(typed, { ...item, pattern: item.features.pattern, gender: item.features.gender })` gives the same result as the server.
- I1: B1 merging replaces the recorder; nothing in this folder changes. The constants `LESSON_CARDS`, `DAILY_TRAINER_CARDS`, `PASS_SHARE` are in `service.ts`; the selection constants in `select.ts`.
