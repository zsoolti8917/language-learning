# B2 Lexicon services
Status: done

## What was built
The real `MorphologyPort` and `DictionaryPort` in `apps/api/src/modules/lexicon/`, and the prompt of the route `reader.gloss`. `container.ts` already calls the two factories, so every module now gets the real ports; the stand ins in `testing/lexicon.ts` stay for F5's own suite test.

| File | Holds |
|---|---|
| `repo.ts` | All SQL: forms by folded spelling (one `form_ascii in (…)` statement joined to `ling.lemma`, split only above 10 000 keys), forms of a lemma, lemmas by id and by `lemma_ascii`, senses, and the insert of run time glosses (`on conflict do nothing`). |
| `service.ts` | Pure logic: rows → `Lemma`, `Sense`, `FormCandidate`, `Paradigm`; candidate order (`matchTier`, `orderCandidates`); `verifyCandidate`; `buildFormTables` (table builder); `GlossAnswerSchema`, `glossRequest`, `glossesToStore`; `LruCache`. |
| `port.ts` | `createMorphologyPort(ctx, cacheOptions?)` → `LexiconMorphology`, `createDictionaryPort(ctx)` → `LexiconDictionary`. |
| `routes.ts` | Unchanged: the module serves no endpoint. |
| `packages/ai/prompts/reader.gloss/v1.ts` | The real prompt (placeholder removed): JSON in, `{ glosses: [{ lemmaId, glosses[] }] }` out, one stable cached block. |

Behaviour:
- **`lookupForms(forms)`**: one key per input (`foldAscii`), one query for every key not in the cache. Candidates of a key are ordered: exact spelling first, then the same letters in other capitals (a capitalised first word finds *mesto*, a lower case word finds *Bratislava*), then other accents; within a tier by `freqRank`, then lemma id. When two inputs share a key (*mesta*, *mestá*), the first input decides the order. Unknown forms → `[]` (cached too).
- **`getParadigm(id)`**: forms in table order (first slot s1…s7, p1…p7, x1…x7, then the form); noun readings carry the noun's gender. Throws `unknown lemma <id>`.
- **`buildFormTables(paradigm)`** → `FormTable[]` `{ gender, columns, rows: [{ case, cells: { sg, pl, x } }] }`: one table for a noun or a pronoun (`x` column for *ja*, *ty*, *kto*, *čo*), one per gender (m_anim, m_inan, f, n) for words whose tags carry a gender (adjectives, *môj*, *ten*, numerals), none for verbs and words without case. Empty rows and columns are dropped (*ľudia* has only `pl`); a cell lists every variant (*človeku*, *človekovi*).
- **`verifyForm(form, want)`**: same letters (capitals ignored, accents not), filtered by lemma, case and number; readings narrowed to the matching ones.
- **`getLemma`**, **`findLemma(text, pos?)`** (folded, trimmed, most frequent first).
- **Cache** per port instance: 20 000 folded forms, 1 000 paradigms, 5 000 lemmas, least recently used out. Cached candidates are frozen. `clearCache()` empties it.
- **`getSenses(ids)`**: senses in `ord` order, `[]` for unknown ids. Not cached (glosses change at run time).
- **`ensureGlosses(ids, { sentenceSk, userId? })`**: reads stored glosses; lemmas that exist and have no sense are asked from `reader.gloss` in **one** call (outside any transaction), with the sentence as context; the answer is filtered (only asked ids, first entry per id, up to 3 distinct trimmed glosses of 1–80 characters) and stored in one `withSystem` transaction with `source: 'runtime'`, `verified: false`, `ord` from 0. A lemma that gained senses meanwhile keeps them. The map holds every input id.

## How to run and test it
`pnpm test --filter api` (or `npx vitest run src/modules/lexicon` in `apps/api`, about 3 s), `pnpm check` (passes: 60 files, 760 tests).

`port.test.ts` (one shared PGlite database for the whole file):
- `runMorphologySuite('real')` and `runDictionarySuite('real')` pass.
- 1,000 words (all 601 mini forms plus unknown words) → `pglite.query` called exactly once; a second call → no query (cache).
- The real statement from `repo.selectFormsByAscii(...).toSQL()` is `EXPLAIN`ed after adding 20 000 forms and `analyze`: the plan uses `form_form_ascii_idx`.
- *mestá* → `p1 p4 p5` first, *mesta* → `s2`; `Mesto` → lemma 20; `Ľudia` → *ľudia* (28) with `p1 p5`; `Má` → *mať*, `Ma` → *ja*; `bratislave` → *Bratislave*; unknown → `[]`.
- Paradigm order and cache, tables for *mesto*, *ľudia*, *ja*, *pekný* (four genders), *mať* (none); `verifyForm` cases; `getLemma`/`findLemma` and `clearCache`; reads on a caller's `withUser` transaction.
- `ensureGlosses` with the mock gateway: one call for the two missing lemmas only (unknown id and lemma with glosses not asked, answer for an unasked lemma ignored), no transaction open during the call, rows stored as `runtime`, the next call reuses them with no model call; the usage row belongs to the calling learner and another learner sees none. No `userId`, `upstream_failed`, invalid answer, budget exceeded → `[]`, nothing stored; a later call stores. A gloss stored by another request during the call is kept.
- Every returned shape is parsed with `FormCandidateSchema`, `ParadigmSchema`, `LemmaSchema`, `SenseSchema`.

`service.test.ts`: tiers and order, variants in a cell, verb and empty tags, the gloss request (from `PROMPTS`, cache mark, input JSON) and answer filtering, `LruCache`.

## Differences from the specification, and why
- **Isolation check**: the module serves no endpoint and reads only `ling`, which holds no learner rows. The test instead shows that the usage row of a gloss call is visible to that learner only.
- **`ensureGlosses` without `userId`** asks nothing (the gateway needs a learner for the budget and the usage row), and a gateway failure (budget, refused, truncated, upstream, invalid output) returns `[]` for the missing lemmas instead of throwing, so a reader text still opens. Other errors are thrown.
- **No local mode mock for `reader.gloss`**: a mock would store invented glosses in `.local/pgdata` forever. In local mode with the mini dataset every lemma has a gloss, so the route is never needed.
- The ports take an **optional last `tx` argument** on every read (`LexiconMorphology`, `LexiconDictionary`), which `ports.ts` does not declare yet (see below).
- `findLemma` trims the text before folding.

## Known gaps and follow ups
- **Calling these ports inside an open transaction**: the reads run on `database.db` (the login role, no transaction). On PGlite (one connection) a read issued while a `withUser` transaction is open waits forever (checked: a plain `pglite.query` inside `pglite.transaction` never returns); on Postgres it takes a second pooled connection. Requested shared change (F5, `ports.ts`): add an optional last parameter `tx?: Tx` to the `MorphologyPort` methods and to `DictionaryPort.getSenses`; the real ports already accept it. Until then, callers must call morphology outside `withUser` (or a cache hit saves them, which is not a guarantee).
- The cache is never invalidated by a content load in another process; a new deploy or `clearCache()` refreshes it. Glosses are not cached.
- Ordering within a key is by tier and rank only; choosing between readings in context is B3's job.
- Not run against real Postgres; the index test runs on PGlite (Postgres 18).

## Notes for packages that depend on this one
- B1, B5, B6, B9: do not call `ports.morphology`/`ports.dictionary` inside `withUser` on PGlite; read before the transaction, or (once `ports.ts` has the parameter) pass `tx`.
- B3/B4: `ensureGlosses(lemmaIds, { sentenceSk, userId })` with all lemmas of a text in one call, between transactions. Missing glosses come back as `[]` when the model is unavailable.
- B6 word page: `buildFormTables(paradigm)` lives in `modules/lexicon/service.ts`; other modules cannot import it (import rules). If the word page needs it on the server, move it to `@app/ling` or expose it through `ports.ts` (shared change).
- Tests that use `createTestApp` now run the real lexicon ports on the test database; to get the stand ins back, pass `ports: { morphology: createMiniMorphology(), dictionary: createMiniDictionary() }`.
- I3: the prompt is `PROMPTS['reader.gloss']` version 1; the request is built by `glossRequest(lemmas, userId, sentenceSk?)` and parsed with `GlossAnswerSchema`.
