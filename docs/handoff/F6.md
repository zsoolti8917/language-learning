# F6 Client skeleton
Status: done

## What was built
The installable shell of `apps/web`: route table, tab bar, guards, typed API client, mock server, login plumbing, local database with outbox, PWA, messages, test setup and a Playwright smoke project.

| Path | Holds |
|---|---|
| `src/main.tsx` | Boot: mock server (mock mode) or service worker registration, dev response validation, outbox triggers, render |
| `src/routes.tsx` | Code based route table, one `lazyRouteComponent` per screen, guards, `createAppRouter`, `createTestRouter`, `ROUTE_PATHS` |
| `src/app/` | `App` + `createAppContext` (providers: Query, Auth, Toast, Router), `TabBar` (+ `tabFor`), layouts, `Placeholder`, not found and error screens |
| `src/features/<f>/*Screen.tsx` | 24 placeholders, one per route (table below) |
| `src/lib/api/` | `api` client, `createApiClient`, `ApiError`, `readTutorStream`/`readSse`, `apiQuery`/`apiKey`, `configureApi`, `endpoints.gen.ts` (generated), `validate.ts` (zod, loaded on demand) |
| `src/lib/auth/` | `AuthClient` interface, dev and Supabase modes, `AuthStore`, `AuthProvider`/`useAuth`, `isFirstRun`, `loadProfile` |
| `src/lib/db/` | Dexie `AppDb` with `kv`, `reviewQueue`, `outbox`, `texts`, `lemmaStatus`; `Outbox`, `outbox`, `useOutbox`, store helpers |
| `src/lib/pwa/` | `registerServiceWorker`, `useUpdatePrompt`, `useIosInstallHint`, `useOnline` |
| `src/lib/{env,ids,query}.ts` | Client variables, `newId()` (UUID v7), `createQueryClient` |
| `src/messages/` | `en.ts` (shell texts), `t`, `format`, `defineMessages` |
| `src/mocks/` | `handlers.ts` (45 defaults from the contract examples + feature handlers), `browser.ts`, `node.ts` |
| `src/test/` | `setup.ts` (global: fake-indexeddb, jest-dom, cleanup, MSW server), `utils.tsx` |
| `scripts/` | `endpoints-gen.ts`, `size-budget.mjs`, `icons.mjs` |
| `e2e-app/` | Playwright at 390 x 844: projects `mock` and `pwa` |
| `public/icons/` | 192, 512, maskable 512, apple touch icon, favicon |

## How to run and test it
- `pnpm check` (web tests: 187 in `@app/web`, including F7's). `pnpm test --filter web` for the web project only.
- `pnpm --filter @app/web dev:mock`: the app on the mock server (same as `VITE_MOCK_API=true`). `dev` alone proxies `/api` to `http://localhost:8787` (`API_URL` overrides).
- `pnpm --filter @app/web e2e`: builds twice and serves with `vite preview` on 5181 (mock) and 5182 (production); `E2E_MOCK_PORT`, `E2E_PWA_PORT`, `E2E_MOCK_DIST_DIR`, `E2E_PWA_DIST_DIR` override, and a server already on a port is never reused.
- `pnpm --filter @app/web e2e:all`: every browser suite (shell, gallery, account, review, reader, cases, words, tutor) one after another, each on free ports with its own build folder (`scripts/e2e-all.mjs`; `e2e:all reader tutor` for some). CI runs it as the `e2e` job after `check`. Result on 2026-11-17: 28 passed. Every one of the 24 routes shows its placeholder (tab routes above a tab bar that ends at 844 px, tabs ≥ 44 px, no console error, no sideways scroll), the login redirect and back, the mock answers `/me`; the manifest and icons pass Chromium's installability check, and after one visit the shell, a never opened screen and a deep link load offline.
- `pnpm --filter @app/web build && pnpm --filter @app/web size`: first load is 152 KB gzip of 200 KB. CI runs this after `pnpm check`.
- `pnpm --filter @app/web test:ui` (F7 gallery) still passes, 16 of 16.

## Differences from the specification, and why
- Branched from the integration commit `d75c98b` (F1 + F2 + F7), because the worktree's HEAD held only F1.
- The client's runtime endpoint table is `src/lib/api/endpoints.gen.ts` (method, path, status, auth, stream), generated by `pnpm --filter @app/web gen:endpoints`; a test fails when it is stale. Types come from `@app/contracts`. This keeps zod and every schema out of the first load. Responses are validated in dev (`warnOnDrift`) and in tests (`parseResponse`).
- Messages: the shell's texts live in `src/messages/en.ts`; each feature keeps its own texts in `features/<f>/messages.ts` through `defineMessages`, so six packages never edit one file. All text stays in messages files, English only.
- First run is defined as `!profile.settings.onboardedAt && !profile.placementDoneAt` (the contract has no onboarding column). M1 ends onboarding with `PATCH /me { settings: { ...settings, onboardedAt: <ISO> } }`.
- In mock mode the app does not register its own service worker: MSW's worker and the PWA worker would claim the same scope. Offline and install checks run on the production build.
- MSW 3 renamed `onUnhandledRequest` to `onUnhandledFrame`.
- Dev login starts signed out (M1 wants a one tap dev login). It accepts the code `123456`, passwords of 8+ characters, and keeps the session in `localStorage` (`app.devSession`). The user id is `EXAMPLE_IDS.user`, so mock data belongs to the dev user.
- The API port is not fixed by the docs; the dev proxy assumes 8787. F5 may change `vite.config.ts` through F6's owner or set `API_URL`.
- `apps/web/tsconfig.json` now includes `scripts/*.ts`, `e2e-app` and `e2e-ui` (as F7 suggested).
- The shell imports `ui` modules by file (`../ui/Toast`), not the barrel, so vaul (with module side effects) stays out of the first load. Features are lazy and may use the barrel.

## Known gaps and follow ups
- Outbox order is global except for retries: a failing item waits while later ones go. Items that depend on each other (create, then update the same note) should be one write, or the later one waits for the first's success in the feature.
- `replaceReviewQueue` replaces the whole table; M2 should flush the outbox (`outbox.syncNow()`) before fetching a new queue.
- Supabase mode is tested with a fake client only; no real project yet (F8). Email templates must send `{{ .Token }}` codes.
- Not tried on a real iPhone.
- Outside owned paths: one step added to `.github/workflows/ci.yml` (build and size budget).

## Notes for packages that depend on this one

**Add a screen.** Replace the placeholder in your folder and keep the export name; the route table already lazy loads it. Routes per folder: account `LoginScreen /login`, `SignupScreen /signup`, `VerifyScreen /verify`, `ResetScreen /reset`, `OnboardingScreen /onboarding`; today `TodayScreen /`, `SettingsScreen /settings`, `AboutScreen /settings/about`; review `ReviewScreen /review`, `DeckScreen /deck`, `NoteScreen /deck/$noteId`; words `WordsScreen /words`, `BandScreen /words/band/$band`, `LemmaScreen /lemma/$lemmaId`; placement `PlacementScreen /placement`; reader `LibraryScreen /read`, `ImportScreen /read/import`, `ReaderScreen /read/$textId`; cases `CourseScreen /cases`, `LessonScreen /cases/lesson/$lessonId`, `TrainerScreen /cases/train`, `PatternScreen /cases/pattern/$patternId`; tutor `ScenariosScreen /tutor`, `ChatScreen /tutor/$conversationId`. Read params with `useParams({ from: '/deck/$noteId' })` (or `strict: false`); links are typed: `<Link to="/lemma/$lemmaId" params={{ lemmaId: '20' }}>`. Need a new route or search params? Ask F6 (shared surface). `/verify` takes an optional `email` search param (`useSearch({ from: '/bare/verify' }).email`). Tab screens render inside `<main>` with the safe areas and room for the tab bar; start with `px-gutter`.

**API client.** `import { api, apiQuery, apiKey, ApiError } from '../../lib/api'`.
- `await api.review.queue({ query: { limit: 50 } })`, `await api.notes.update({ params: { id }, body: { suspended: true } })`, `await api.profile.get()`. Input: `params` and `body` when the endpoint has them, `query` optional; second argument `{ signal }`. 204 endpoints resolve to `undefined`. Function names are the endpoint names: `api.<prefix>.<action>`.
- Queries: `useQuery(apiQuery('declension.course'))`; invalidate with `queryClient.invalidateQueries({ queryKey: apiKey('declension.course') })` or `['api', 'notes.list']` for all inputs.
- Errors reject with `ApiError { status, code, details, isNetwork, isRetryable, retryAfterSeconds }`; `code` is a contract `ErrorCode` or `'network'` (status 0). A 401 refreshes the token once and repeats the call; a failed refresh signs out.
- Stream: `const stream = await api.tutor.sendMessage({ params: { id }, body: { clientId, content } })` (HTTP errors reject here, before any event), then `for await (const ev of stream)` yields typed `TutorStreamEvent`s and ends after `done` or `error`; `stream.cancel()` stops it. `readTutorStream(body)` parses any `text/event-stream` body.
- Ids: `newId()` from `lib/ids` for every client made id.

**Mock handlers.** Defaults replay `examples[name].ok[0]`. To change the mock for your feature, create `features/<f>/mocks.ts` exporting `export const handlers = [mockEndpoint('review.queue', myQueue), ...]`; it is picked up by glob and wins over the defaults in the browser and in tests (Vitest too). **Import the helpers from `src/mocks/endpoint`** in a feature's `mocks.ts` (`import { mockEndpoint } from '../../mocks/endpoint'`): `src/mocks/handlers` loads every `features/*/mocks.ts` by eager glob, so importing it back from one of them is an import cycle ("Cannot access … before initialization"). `src/mocks/handlers` still re-exports every helper, and tests keep using `src/test/utils`. Helpers: `mockEndpoint(name, bodyOrResolver, { status?, once?, delayMs? })` (resolver gets `{ request, params, query, body }` typed), `mockError(name, code, { details })`, `mockNetworkError(name)`, `sseResponse(events, { delayMs })`, `endpointPattern(name)` (for a plain `http.*` handler that falls through by returning `undefined`), `exampleHandler`, `defaultHandlers`; for `tutor.sendMessage` pass an event array. Per test: `server.use(...)` (reset after each test). `src/lib/api/client.test.ts` checks every endpoint against the default handlers only (it puts `defaultHandlers` first), so feature overrides do not break it.

**Local database and outbox.** `import { db, outbox, useOutbox, kvGet, kvSet, replaceReviewQueue, getReviewQueue, applyCardSnapshots, storeText, getStoredText, setLemmaStatuses, getLemmaStatus, registerApplier, registerMerger, clearLocalData } from '../../lib/db'`.
- Writes: `await outbox.enqueue('review.submitAnswers', { body: { clientId, answers: [a] } })`. Waiting items of `review.submitAnswers`, `declension.submitAttempts` and `words.triage` merge into one batch (≤ 200), unless `{ merge: false }`. Triggers: start, `online`, foreground, each enqueue, and `outbox.syncNow({ includeFailed? })`.
- Network failure: everything waits. 5xx, 408, 429: that item retries with backoff (or `retryAfterSeconds`), others go on. Other 4xx: `failed`, shown in `useOutbox().failed`.
- A server answer replaces local state: built in for `review.submitAnswers` (card snapshots into `reviewQueue`), `lemmas.setStatus` (`lemmaStatus`), `texts.update` (`texts`). Add yours with `registerApplier(name, (response, input, db) => …)` at module load of your feature.
- `useOutbox()` → `{ pending, failed, syncing, lastSyncAt, syncNow }`.

**Auth.** `const { status, session, mode, signIn, signUp, verifyCode, resendCode, requestPasswordReset, updatePassword, signOut } = useAuth()` from `lib/auth`. `status`: `loading | signedIn | signedOut`. Actions reject with `AuthError { code }`: `invalid_credentials`, `invalid_code`, `weak_password`, `email_taken`, `rate_limited`, `network`, `unknown`. Sign up: `signUp` → `verifyCode(email, code, 'signup')`. Reset: `requestPasswordReset` → `verifyCode(email, code, 'recovery')` → `updatePassword`. `signOut` clears the local database and the query cache. The guards react to the change themselves. After login, go to `useSearch({ from: '/login' }).redirect ?? '/'`.

**PWA (M1).** The tab layout shows the offline indicator and the update prompt above every tab screen (`lib/pwa/notices.tsx`: `OfflineIndicator`, `UpdatePrompt`, `PwaNotices`). `useUpdatePrompt()` → `{ needRefresh, offlineReady, update, dismiss }`; `useIosInstallHint()` → `{ show, dismiss }` (once); `useOnline()`.

**Messages.** Shell: `t('tabs.today')`. Feature: `export const m = defineMessages({ due: '{count} due' })` in `features/<f>/messages.ts`, then `m.t('due', { count })`. Pass texts to `ui` props.

**Tests.** Global setup is automatic (fake IndexedDB, jest-dom, cleanup, MSW with unhandled requests failing). From `src/test/utils`: `renderRoute('/review', { auth?: 'signedIn' | 'signedOut' | fakeAuthClient })` renders the whole app (returns `router`, `context`); `renderWithProviders(<X />)`; `server`; `freshDb()`; `testOutbox({ isOnline, now, backoff })`. `createDevAuth({ storage: null, signedIn: true })` is a ready fake login. Playwright for your feature can reuse `e2e-app/playwright.config.ts` patterns (dev session in `localStorage` key `app.devSession`).
